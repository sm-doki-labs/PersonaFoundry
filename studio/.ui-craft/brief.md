# 캐릭터 공장 연결 작업 디자인 기준

2026-10-30 현재 design.md의 기존 결정과 토큰을 이번 공정 연결에도 적용한다.

- 대상은 비개발 기획자와 라이브 시연 관객이다. 화면 이름은 쉬운 한국어를 먼저 쓰고 모델 ID·추론 강도는 상세로 접는다.
- d-ops·시연·따로 연 관문 화면은 기존 Liquid Glass, 짙은 중립색·세이지/모래/장밋빛 상태색, Pretendard, 기록 패널 토글을 보존한다. 진행 화면(factory.html)과 그 안의 관문 시트는 아래 Foundry 기준을 따른다(2026-11-07 사용자 지시, D-0102).
- 기본 공장 화면은 실제 서버의 실행·관문·산출물을 보여 준다. 서버가 단일 상태 원천이며 타이머로 진행하지 않는다. 옛 시연은 ?mode=demo로 명시할 때만 실행한다.
- 선택 버튼은 기본 개발 확인·시연·시연 전 최종 점검, 호출 경로는 개발 연결·별도 테스트 서버다. 미설정 서버는 선택하지 못하며 오류 후 기존 선택을 보존한다.
- 현재 선택과 과거 생성 출처를 분리한다. 최종 점검을 선택한 것만으로 실제 실행·품질 검증 완료로 보이지 않는다.
- 키보드·focus-visible·Escape·닫은 뒤 포커스 복귀를 보장한다. 움직임은 최소화하며 prefers-reduced-motion을 따른다.
- 1280/1512 노트북 화면에서 내용은 패널 안에서 스크롤한다. 배경의 시연 컨트롤을 가리더라도 닫기·연결 상태는 항상 찾을 수 있어야 한다.

토큰 원천은 shared/glass.css, 기존 정보 구조와 학습된 제약의 원천은 design.md다. 구현 계약과 작업 분담은 plans/2026-10-30-agentic-runtime-connection.md를 따른다.

- 학습된 연결 범위: 실제 연결 완료는 화면의 시작·후보 선택·수정·승인이 기존 실행기를 움직이고, 결과와 대기/실패가 실제 기록으로 복원되는 상태다. 설정·조회 패널만으로 연결 완료라고 설명하지 않는다.
- 실제 공장 현장은 백엔드의 갈래 정의를 사용한다. 옛 아이소메트릭 벨트 각본은 명시적 demo에만 남긴다. 실제 모드에서 지원하지 않는 제어는 노출하지 않는다.

## Foundry 기준(2026-11-07, D-0102)

- 형태: 운영 콘솔(operational console). 앱 셸 3단(왼쪽 탐색 사이드바, 가운데 캔버스, 오른쪽 인스펙터), 검토는 오른쪽 시트.
- 브랜드: 워드마크 "Foundry", 부제 "캐릭터 공장". 로고는 보라 둥근 사각형에 F와 불꽃 점. 브랜드 보라는 선택·초점·로고에만 쓴다. 주 버튼은 밝은 화면에서 거의 검정, 어두운 화면에서 거의 흰색.
- 색: 중립색 우선 + 의미색 + 강조색 하나. 중립 Radix Slate, 브랜드 Radix Violet #6e56cf, 진행 Radix Blue, 상태 GitHub Primer(주의 #9a6700, 성공 #1a7f37, 위험 #d1242f, 완료 #8250df).
- 토큰: 기본 색 → 의미 → 부품의 세 층, 접두사 --fd-. 부품은 의미 토큰만 쓴다. 원천은 shared/foundry-tokens.css(studio와 web/static 두 사본, 시험으로 같음을 확인).
- 상태는 점 + 글자로 함께 보인다. 4pt 간격, 모서리 4/6/8/12, 1px 선, 그림자는 시트·메뉴처럼 떠 있는 층에만.
- 테마: 시스템 따르기·밝게·어둡게. localStorage fd-theme, 첫 그림 전에 적용. 관문 시트에는 skin=foundry&theme=로 넘긴다.
- 글꼴 Pretendard, 숫자는 고정폭(tabular-nums), 문구는 해요체.

## 개요·그래프 보기(2026-11-07, D-0103)

- 정보 구조: 작업 공간(전체 캐릭터 개요 · 받은 일 대기열) → 캐릭터(진행 화면) → 단계(인스펙터·시트). 개요는 목록–상세, 받은 일은 캐릭터를 가로지르는 작업 대기열이다. 할 일 수는 어디서나 같은 함수로 센다.
- 그래프는 화면 맞춤이 기본이다. 확대·축소·맞춤·크게 보기는 선택이고, 휴대폰 폭에서는 끈다. 무한 캔버스·칸 끌어 옮기기는 하지 않는다(팀 위치가 순서를 뜻한다).
- 돈이 들거나 되돌리기 어려운 결정은 두 단계(비용 확인 → 유료로 실행, 반려 확인)로 한다. 서버에 없는 금액은 '견적 없음'·'—'로 적는다.
- 상태는 정직하게: 실패는 단계 실패로 기록되어야 하고, 도는 작업 없이 멈춘 흐름은 '이어서 실행'으로 알린다.
