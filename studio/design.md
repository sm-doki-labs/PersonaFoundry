# 캐릭터 공장 디자인 문서

- 기준일: 2026-10-30
- 대상: 시안 `d-ops.html`(캐릭터·진행 현황·공장 현장), `c-glass.html`(작업실), `shared/*`
- 함께 볼 문서: [공장 현장 개선 계획과 진행 기록](plans/2026-10-28-floor-improvement-plan.md), [라이브 시연 대본](plans/2026-10-29-live-demo-script.md)
- 시안의 시간·비용·장면 문구·이미지는 데모 각본이다. 단계 코드, 에이전트, 관문 코드, 재시도 상한은 공장 문서(`agentic-character-factory`)를 따른다.

## 1. 제품과 사용자

캐릭터 공장은 비개발 기획자가 캐릭터 한 명을 만드는 멀티 에이전트 SaaS다. 기획, 비주얼, 영상, 마케팅, 페르소나, 데이터셋, 학습의 7개 팀 라인에서 AI 에이전트 작업 20개가 의존 관계를 따라 병렬로 돈다. 사람은 결재 관문에서 고르거나 승인할 때만 개입한다.

| 사용자 | 주로 쓰는 화면 | 바라는 것 |
|---|---|---|
| 기획자(실사용) | 캐릭터 목록, 진행 현황, 작업실 | 결재할 일과 문제를 바로 찾고, 클릭으로 고른다 |
| 처음 보는 관객(시연) | 공장 현장 크게 보기 | 말 설명만 듣고 공장이 어떻게 돌아가는지 안다 |

시연은 노트북 화면 공유로 하는 라이브 데모다. 그래서 "있어빌리티"와 정확성을 함께 지킨다.

## 2. 디자인 원칙

1. **고르는 UI가 먼저다.** 타이핑은 옵션이다. 후보, 칩, 버튼으로 결정하고, 직접 쓰기와 메모는 보조로 둔다.
2. **모든 움직임과 클릭 대상은 실제 데이터와 1:1이다.** 벨트 위 상자, 승인 순간의 선, 진행 숫자는 작업·관문·산출물 revision에서 계산한다. 데이터와 무관한 장식 움직임은 쓰지 않는다.
3. **절제된 색.** 짙은 회색 바탕에 상태색 세 가지만 쓴다. 오래 봐도 눈이 피로하지 않아야 한다.
4. **효과는 명시적으로, 화려하지 않게.** 상태가 바뀐 순간을 짧게 보여 주고 사라진다(예: 승인 순간 표시 2.8초).
5. **같은 사실을 여러 곳에 겹쳐 보여 주지 않는다.** 지금 일은 화면에, 지나간 일은 접히는 기록 패널에 둔다.
6. **캐릭터 단위로 묶는다.** 완료된 캐릭터와 진행 중인 캐릭터, 그 아래 작업 요청과 자산 revision이 모두 캐릭터에 매달린다.
7. **쉬운 말이 먼저, 코드는 보조.** 화면에는 "배경 고르기"를 쓰고 `G4a`, `fr2`, `codex_image` 같은 코드는 툴팁과 상세 창에 둔다.
8. **시안은 구현의 기준이다.** 동작이 정확해야 하므로, 바꿀 때마다 자동 검사로 의존 관계와 상태 정합성을 확인한다.

## 3. 시각 스타일: 리퀴드 글래스

세 가지 스타일 시안(A 시네마틱 다크 스튜디오, B 에디토리얼 매거진 + 벤토, C 리퀴드 글래스)을 비교해 **C 리퀴드 글래스**를 골랐다. 반투명 유리 패널을 쓰고, 고른 얼굴 사진의 색이 흐리게 번져 배경 분위기가 된다. 운영 화면과 작업실이 같은 스타일과 같은 색을 쓴다.

### 토큰 (`shared/glass.css` `.theme-glass`)

| 분류 | 값 |
|---|---|
| 바탕 · 글자 | `--bg #16181d`, `--text #e3e5e9`, `--muted` 66%, `--faint` 58% |
| 강조(단색 버튼) | `--solid #cfd3da` / `--solid-ink #15171c` |
| 상태색 | `--ok #93b5a1` 세이지(완료·승인), `--warn #c9b07e` 모래(사람 결재 대기), `--bad #c9938d` 장밋빛(재시도·사람 필요·실패) |
| 유리 | 위아래 6%→2.5% 흰빛 그라디언트, `blur(24px) saturate(110%)`, 안쪽 윗선 하이라이트와 아래 그림자 |
| 모서리 | 패널 22, 카드 16, 안쪽 12, 컨트롤 999(알약) |
| 글자 크기 | 11 · 12 · 13 · 14 · 15 · 18 · 24 · 40px |
| 컨트롤 높이 | 24 · 30 · 36 · 38(탭) · 44px |
| 글꼴 | Pretendard Variable(현재 CDN, 로컬화는 남은 일) |

### 색 쓰는 규칙

- 모래색은 **사람 결재를 기다릴 때만** 쓴다. 앞 작업을 기다리는 라인은 중립색이다.
- 장밋빛은 재시도 중, 사람 필요, 실패에만 쓴다.
- 세이지는 완료, 승인, 통과에 쓴다.
- 진행 중은 색 없이 밝은 글자와 깜빡이는 점으로 보인다.
- 머리 줄 요약처럼 값이 0인 항목은 색 점을 끈다.

### 상태 표 (`shared/status.js`)

상태 이름과 색은 이 표 한 곳에서만 정한다. 화면 코드는 상태 글자를 직접 쓰지 않는다.

| 대상 | 상태 |
|---|---|
| 작업 요청(job) | 시작 전 · 실행 중 · 일시정지 · 결재 대기 · 사람 필요 · 완료 · 취소됨 |
| 팀·작업(task) | 대기 · 작업 중 · 일시정지 · 결재 대기 · 예산 대기 · 재시도 중 · 사람 필요 · 완료 · 취소됨 |
| 시도(attempt) | 진행 중 · 성공 · 실패 · 중단 |
| 관문(gate) | 결재 전 · 결재 대기 · 결재됨 |
| 자산(asset) | 아직 없음 · 대기열 · 만드는 중 · 결재 대기 · 사람 필요 · 승인 |
| 캐릭터(life) | 기획 중 · 제작 중 · 출시 준비 · 출시됨 |

### 공통 상단바 (`shared/appbar.js`)

모든 화면이 같은 자리에 같은 길잡이를 둔다: 브랜드 · [캐릭터 | 작업실] 탭 · 위치(캐릭터 › 작업 요청) · 실행 상태 · 일시정지/취소 · 시연 도구 · 알림 · 사용자.

- 작업실과 운영 화면을 오가도 **탭 토글이 같은 자리에 남는다.** 상단 내용이 바뀌어도 사용자가 "토글로 넘어갔다"고 느끼게 한다.
- 작업실 탭 배지는 고를 일이 몇 건인지 보여 준다.
- 진행 현황과 공장 현장은 같은 데이터의 두 보기다. 섹션 머리의 "진행 현황 | 공장 현장" 전환으로 오간다.

## 5. 결재 관문

| 관문 | 이름(화면) | 종류 | 팀 | 열리는 조건 | 승인하면 시작 |
|---|---|---|---|---|---|
| G1 | 얼굴 고르기 | 고르기 | 비주얼 | 외모군·얼굴 완료 | 기준 사진 |
| G3 | 기획안 고르기 | 고르기 | 기획 | 기획안 3개 완료 | 배경 9장, 소개 문구, 특질 시트 |
| G4a | 배경 고르기 | 고르기 | 비주얼 | 배경 9장 완료 | 챕터 사실 |
| G4 | 이미지 승인 | 승인 | 비주얼 | 완성 이미지 완료 | 대기 영상, 썸네일, G5b 결재 |
| G5b | 움직임 고르기 | 고르기 | 영상 | 완성 이미지 완료 **그리고 G4 승인** | 행동 영상 |
| G6 | 페르소나 승인 | 승인 | 페르소나 | 프롬프트 완료 | 대화 재작성 |
| G7 | 표본 검수 | 승인 | 데이터셋 | 클러스터 증강·품질 검사 완료 | 파인튜닝 |
| G9 | 출시 승인 | 승인 | 포장대 | 모든 작업 완료 | 출시본 `rl1` 고정 |

- 얼굴은 G1에서 **한 번만** 고른다. 기준 사진(S2)은 고른 얼굴로 자동 생성하고 동일인 판정을 자동 검사한다. 별도 사람 관문(옛 G2)은 없앴다(공장 문서 D-0042).
- 고르기 관문은 작업실에서만 결정한다. 승인 관문은 공장 위 표시나 결재함에서 바로 승인한다.
- 승인 관문은 메모를 붙여 **수정 요청**할 수 있다. G4는 챕터별로 승인/수정을 고르고 요청한 장만 다시 만든다. 다시 올라오면 전후를 나란히 비교한다(G4는 그림, G6·G7은 문단).

## 6. 작업실

- 한 화면에 후보를 나란히 보여 주고, 눌러 고르고, "이 ○○로 확정"으로 끝낸다.
- 기획안 후보는 같은 상황(예: 상대가 30분 늦는다고 연락)에서 **무엇을 먼저 하는지**로 비교한다. 캐릭터성은 같은 상황에서의 다른 행동이다.
- 고칠 점은 칩("더 다정하게", "말수 더 적게" 등)으로 고른다. 직접 쓰기와 다시 만들기는 보조다.
- 확정하면 도장과 토스트가 뜨고 1.3초 뒤 들어온 화면으로 돌아간다. 돌아가면 공장 현장이 그 결재의 **승인 순간 표시**를 띄운다.
- 왼쪽 캐릭터 카드는 고른 결과가 쌓이며 채워진다(얼굴 → 이름·소개 → 챕터 이미지 → 움직임 영상).

## 7. 공장 현장

### 구성

| 요소 | 뜻 | 보이는 방식 |
|---|---|---|
| 라인 | 팀 하나 | 바닥 띠, 왼쪽 라인 이름 + 상태 칩 + 이유 한 줄("배경 고르기 결재 기다림") |
| 작업대 | 작업 하나 | 상자 모양. 이름표는 늘 보이고, 일하는 동안 로봇팔이 움직인다 |
| 차단기 | 사람 결재 | 이름표 앞 차단기 기호. 대기 중이면 모래색 표시와 [고르기 →] / [검토][승인] |
| 상자 | 산출물 | 산출물 단위(배경 9장 → 상자 9개, 대화 2,400개 → 6묶음). 의존대로 다음 작업대나 관문까지만 간다 |
| 포장대 | 캐릭터 | 모든 라인의 산출물이 모인다. 캐릭터 카드(라인 완료 n/7, 자산 승인 n/13)와 G9 |

### 일하는 작업 보여 주기

- 바닥에는 작업대 바로 앞, **자기 라인 안**에 한 줄 칩: 이름 · 진행. 진행은 하나만 쓴다(개수가 있으면 "완료 수/전체", 없으면 %).
- 무엇을 하는지는 오른쪽 위 **"지금 일하는 에이전트" 목록**에 라인 순서대로 쌓인다: 팀 · 작업 · 진행 / 한국어 역할명 · 지금 하는 일. 영어 에이전트 이름은 기본 보기에서만 보인다.
- 목록 줄과 바닥 칩은 짝이다. 하나에 마우스를 올리면 둘 다 밝아진다.
- 목록 제목 숫자는 머리 줄 "작업 중 에이전트"와 같은 기준으로 센다(사람 필요는 장밋빛 줄로만 남긴다).

### 이름표 배치

겹치면 숨기던 방식을 버리고 자리를 찾는다: 제자리 → 좌우 12px → 한 줄 아래(라인 간격이 충분할 때, 작업대만) → 작업대·차단기 위 → 관문은 차단기 기호만. 자리 계산은 접힌 크기가 아니라 **전체 이름 크기**로 한다(깜빡임 방지). 정지 화면에서 이름표 상태 변화는 0회여야 한다.

### 상태 효과

| 순간 | 효과 |
|---|---|
| 결재 요청 | 모래색 표시가 관문 오른쪽(막히면 왼쪽)에 뜨고 링이 퍼진다 |
| **결재 승인** | 관문에서 실제로 시작할 수 있게 된 작업까지 선이 그려지고, 해당 작업대·라인 이름이 밝아진다. 세이지색 "기획안 고르기 확정 → 비주얼 · 마케팅 · 페르소나 시작" 문구. 2.8초, 일시정지·구성 보기 중에는 멈춰 남는다 |
| 재시도·사람 필요 | 작업대와 칩이 장밋빛, 버려진 상자가 벨트 밖으로 튕겨 나간다 |
| 수정 요청 반영 | 관문 이름표가 "수정 반영 중 · 2장", 칩에 "수정 반영 중" |
| 라인 시작 전·완료 | 시작 전 라인은 흐리게, 완료 라인은 도크가 세이지 |

"시작할 수 있게 된 작업"은 `ops.js unlockedBy(gid)` 하나로 계산한다. 그 관문을 의존으로 갖고 나머지 의존도 끝난 작업, needs가 모두 승인된 관문이다. 승인 표시와 기록·알림 문구가 같은 값을 쓴다.

### 따라가기(포커스)

작업대를 한 번 누르면 그 작업과 앞뒤 의존만 밝히고 의존을 호로 잇는다. 카메라는 지금 일이 일어나는 곳(기다리는 앞 작업 → 자기 → 결과를 쓰는 뒤 작업)을 따라간다. 두 번 누르면 상세 창. 따라가는 동안 상자를 누르면 산출물 팝오버(그림, revision, 만든 시도와 계기, 가는 곳)가 뜬다. 전체 둘러보기, 추적 복귀, Esc.

### 크게 보기 · 구성 보기 · 기록 패널

| 기능 | 조작 | 동작 |
|---|---|---|
| 크게 보기 | F / 버튼 | 지표 줄과 사이드를 접고 공장이 화면을 채운다. 지표는 머리 줄 한 줄 요약. 범례와 안내 문구는 숨긴다. 상태 기억 |

## 9. revision과 기록 규칙

- 사람이 다시 실행하거나 수정 요청하면 산출물 revision이 오른다(`fr1 → fr2`). 자동 재시도는 같은 revision 안의 시도다.
- revision 번호는 정의의 시작 번호를 반영한다(기획안은 `pr2`부터). 접두는 산출물마다 다르다(마케팅 `mk`, 출시본 `rl`).
- 다시 실행하면 뒤에 이어진 작업과 결재도 함께 되돌린다.
- 결재와 수정 요청은 결재 이력(`S.reviews`)에, 시도는 계기·메모·revision과 함께 남는다.

## 16. 텍스트 제작 공정 연결(2026-10-30)

[연결 계획표와 검증 결과](plans/2026-10-30-text-pipeline-connection.md)를 따른다. 기존 글래스 스타일·공장 배치·기록 토글을 유지하고 상단에 **텍스트 공정** 버튼을 추가했다. 패널은 모델 프로필·호출 경로와 아홉 역할의 배정을 읽고, 실제 캐릭터의 단계·관문·최근 텍스트 호출·산출물 출처를 표시한다. 모델 ID와 추론 강도는 상세 펼치기에 둔다.

개발 확인/시연/시연 전 최종 점검과 개발 연결/별도 테스트 서버를 선택한다. 설정 미완료·연결 실패·실행 중 작업은 선택을 막고, 저장 실패 시 이전 선택을 유지한다. sourceGeneration은 과거 생성 기록이고 selectedConfiguration은 현재 선택이므로 서로 다른 것으로 보존한다. 최종 점검 선택은 검증 완료가 아니다. 모델 생성과 관문 결정은 기존 워크숍에서 수행하며 새 패널에서 자동 실행하지 않는다.

공장 현장과 작업대의 시간·비용·호출 ID는 여전히 시연 각본이다. 텍스트 작업대의 모델 배정은 새 덱의 basic_test 스냅샷으로 갱신하고, 프롬프트 조립은 호출0회로 표시한다. 실제 설정과 실제 기록 패널은 같은 서버의 API로 별도로 읽는다. 각본의 과거 캐릭터 카드와 실제 서버의 캐릭터 목록을 같은 데이터라고 표시하지 않는다.

연결한 backend는 `/Users/johnhuh619/projects/character-factory-poc`다. 현재 이 루트에는 등록 캐릭터가 없어 빈 상태를 보여 준다. 이전 agentic-character-factory나 실험별 생성 루트의 결과는 보존하며 자동 합치지 않았다. 기존 문서의 구형 G2 구현 설명을 이번 연결된 backend의 현재 상태로 간주하지 않는다.

## 17. 실제 에이전틱 공장 화면(2026-10-30, 현재 동작)
