## 1. PoC가 증명할 것

3일 뒤 다음이 참이다.

1. 합성 브리프로 S1 → G1 → S2 → … → G9 → 릴리즈 패키지 → 우리 앱 일회용 DB 적재까지 가짜 공급자로 네트워크 없이 한 번에 통과한다. 여성·남성 브리프 두 개로 돌려 두 갈래가 섞이지 않는 것을 확인한다(PRD §14 수용 조건 1을 S9~S11·내보내기까지 넓힌 것).
2. 사람이 워크숍 화면에서만 모든 관문을 눌러 같은 흐름을 끝까지 갈 수 있다. 명령어를 쓰지 않는다(P-04).
3. 가짜 공급자 자리에 실제 공급자를 넣는 것은 설정 변경뿐이다. 실제 어댑터는 모두 코드로 있고, 실행 전 호출 계획·비용 추정(dry run)을 내며, 녹화 응답 또는 가짜 서버로 계약 테스트를 통과한다. 순위 수집·이미지·LLM 어댑터는 실제로 한 번씩 불러 확인한다. Gemma·Vertex 학습과 영상(`xai_video`, Grok OAuth)은 실제로 부르지 않고 dry run까지만 한다(P-24).

파이프라인이 만드는 패키지(코드가 내야 하는 형식):

- 외모: 레퍼런스 근거 보고서, G1에서 고른 얼굴, 기준 이미지, 외모 명세
- 기획: 기획서, 챕터 사실, 챕터 완성 이미지 3장(9:16)
- 영상 세트: 소개 영상과 챕터 동작 영상. 실제와 같은 ID·파일 형식·메타데이터로 페르소나에 연결된다(P-03)
- 대화 두 경로(P-02): 긴 프롬프트(프롬프트 경로)와, SFT용 짧은 프롬프트 + 데이터셋 revision + 학습 결과 두 개(`model_binding`, Gemma·Gemini) + 비교 평가 보고서(SFT 경로)
- 매니페스트: 모든 ID·revision·해시와 관문 승인 기록

"원하는 서비스 DB에 바로 넣는다"(P-01)는 형식 중립 패키지 하나와 대상별 변환기로 실현한다. PoC는 우리 앱 변환기 1종(api-svc 프로필 카드·단계, chat-svc 페르소나·챕터 사실)을 만들고 일회용 DB에 실제 스키마로 넣어 확인한다(P-09).

| 1일차 오전 | 0 계약을 먼저 쓴다. 동시에 계약이 필요 없는 A·B·F와 G의 서버 뼈대를 시작한다 |
| 1일차 오후 ~ 2일차 오전 | C·D·E를 계약대로 구현, G 관문 화면 |
| 2일차 오후 | H 통합, 전체 오프라인 흐름 테스트 |
| 3일차 오전 | 워크숍으로 전체 흐름 수동 통과(브라우저 확인), 일회용 DB 적재, 순위 수집·이미지·LLM 실제 1회 확인(P-24, 사용자 실행 지시 뒤) |
| 3일차 오후 | PRD·명세·LLD·현재 상태·알려진 문제·검증 기록·인계 문서 정리 |

계약(0)이 늦으면 C·D·E가 함께 밀린다. 계약은 1일차 정오까지 끝낸다.

## 8. 합격 기준

| 대상 | 기준 |
|---|---|
| 전체 흐름 | 여성·남성 합성 브리프 두 개가 가짜 공급자로 S1 → G9 → 패키지 → 일회용 DB 적재까지 네트워크 차단 상태에서 통과한다 |
| 워크숍 | 같은 흐름을 브라우저에서 관문만 눌러 끝까지 간다(실제 화면 확인) |
| 노드 성숙도 | 범위 안의 모든 노드가 L1 이상. 이번 PoC는 L2를 새로 주장하지 않는다(노드 성숙도 규칙) |
| 실제 어댑터 | 모두 dry run과 계약 테스트 통과. 순위 수집·이미지·LLM은 실제 1회 호출로 산출물이 계약에 맞는다. 학습·영상은 dry run의 호출 계획·비용 추정이 나온다 |
| 회귀 | `scripts/check.sh` 통과(기존 테스트 포함) |
| 문서 | PRD → 명세 → LLD가 구현과 맞고, 새 결정이 결정 기록에 있다 |
| 비용 | 원장 합계 $200 이하 |

## 9. 위험

- 계약 갈래가 늦으면 병렬 갈래가 막힌다. 1일차 정오를 넘기면 C·D·E 가운데 D를 먼저 세운다.
- 순위 출처가 자동 수집을 허용하지 않으면 다른 출처를 찾는 동안 B가 밀린다(P-21). 녹화 응답 테스트는 출처와 무관하게 먼저 만든다.
- Grok OAuth 토큰으로 영상 생성 호출이 되는지, 그 사용이 xAI 이용 조건에 맞는지 미확인. 계약 테스트는 가짜 서버로만 한다.
- 데이터셋 대량 작성 처리량은 실제 캐릭터를 만들 때의 문제다. PoC에서는 동시 호출 상한과 재시도·첫 성공 보존을 코드로 갖추는 데까지 간다.
- 원본 SFT가 없는 캐릭터에 소민 배합을 적용한 결과는 검증된 적이 없다. 기본값으로만 둔다.
- 앱 두 저장소의 스키마가 바뀌면 변환기가 깨진다. 변환기는 대상 마이그레이션 head를 기록하고, 맞지 않으면 적재 전에 멈춘다.
