# 윤서진 프롬프트 감사: 성격이 약해지고 상담체가 생긴 경로

2026-10-29. [실제 생성·Gemini42응답](2026-10-29-trait-persona-gemini-live.md)을 프롬프트 조립과 데이터 전달 관점에서 역추적했다. 추가 유료 호출과 제품 수정은 없다. 실행 당시 제품263파일의 해시가 현재와 같고, 같은 입력으로 최종6,683자를 정확히 재현했다.

**가장 먼저 고칠 대상은 최종 프롬프트 조립이다. 기본 성격을 담은 필드가 빠지고, 최종 예시는 조건 준수와 관계 조율을 우선해 골랐다.** 원래 말투는 중간 작성기에만 전달됐으며 최종 Gemini에는 새로 작성한 일부 예시만 들어갔다. 이 전달 경로는 확인된 사실이다. 각 요인이 실제 대화 품질에 끼친 효과 크기는 대조 호출 전에는 가설이다.

## 1. 기본 성격이 최종 조립에서 누락됐다

| 단계 | 무뚝뚝함 | 자존심 | 확인한 내용 |
|---|---|---|---|
| 제작자 기본 입력 | 있음 | 있음 | 성격 원문에 두 성향을 직접 썼다. |
| 선택한 기획 pr1 | 있음 | 있음 | `coreTraits`에 그대로 구체화됐다. |
| 특질 시트 tr1 | 있음 | 있음 | `card.expressedTraits.core`, `choice.expressionIntensity`, `dialogueHabits`에 남았다. |
| blueprint | 있음 | 직접 명시 없음 | 무뚝뚝함은 주로 `voiceProfile`에 남았다. |
| 최종 시스템 프롬프트 | 직접 명시 없음 | 직접 명시 없음 | `coreTraits`와 `voiceProfile`을 조립하지 않았다. |

단어가 없다고 의미가 반드시 없다는 뜻은 아니다. 다만 여기서는 원본 필드를 실제로 제외하는 코드와 최종 본문을 함께 확인했다. ‘필요를 먼저 듣고 조정한다’와 ‘혼자 상상한다’는 추가 행동 원문은 최종에 직접 들어갔지만, 기본 성격의 무뚝뚝함·자존심은 그에 상응하는 지시를 받지 못했다.

구체적인 위치:

- `stages/s8_prompts/source.py:45`의 `project_plan`은 coreTraits·contrastTrait·wantsAndFears 등을 담는다. 그러나 `:54`의 `canonical_sections`는 신원·생활·말투·챕터만 조립하며 핵심 성격 구역을 만들지 않는다.
- `stages/s8_prompts/choice_voice.py:269`는 성격 구역에 `ordinaryModes`와 추가 선택 특질만 쓴다. `:271`은 말투 구역을 `voice.rules + plan.voiceSummary`로 만든다. `bp.voiceProfile`과 trait sheet의 핵심 성격·표현 강도를 전달하지 않는다.
- blueprint의 실제 목표인 “기본은 차분하고 다정하되 무뚝뚝하다. 친해지면 장난기가 드러나고…”도 최종에 없다. ‘필요 확인→자기 답→조정 질문’ 순서를 매번 반복하지 말라는 개인별 지시도 `voiceProfile.avoidRepetition`에 있으나 이 필드는 최종에 포함되지 않는다. 공통 규칙의 반복 금지 지시는 별도로 남아 있다.

따라서 ‘모델이 입력한 성격을 무시했다’는 진단만으로는 부정확하다. 제작자가 입력한 성격 중 일부는 최종 소비 모델까지 명확하게 전달되지 않았다. 해시·출처가 연결돼 있어도 모든 성격 의미가 최종 본문에 포함됐다는 보장은 아니다.

## 2. 예시 선택은 캐릭터 표현보다 규칙 커버리지를 우선했다

생성된12장면/캐릭터34발화 가운데 최종에는 `d01 / d07 / d08 / d12`의13발화가 들어갔다. 아침 인사, 칭찬과 일정 조율, 지각, 관계 보류 장면이다. 정작 짧은 장난을 보여주는 d06은 제외됐다.

생성된 d06에는 다음 대사가 있었다.

> 다섯 개면 알람도 교대 근무하겠네 ㅋㅋ

즉 생성기가 장난을 전혀 만들지 못한 것은 아니다. 최종 예시 선정에서 그 표현을 전달하지 않았다.

`choice_voice.py:30`은 dialogueId를 정렬하고, 4개 조합 중 태그·선택규칙을 모두 덮는 **첫 조합**을 반환한다. 자연스러움·캐릭터성·말투 원천과의 유사도·중복을 평가해서 고르지 않는다. 이번 데이터에서 유효 조합은47개이며 그중6개는 d06을 포함한다. `d06 / d07 / d08 / d12`도 같은 규칙·태그 요구를 만족한다. 따라서 장난 예시 제외는 ‘4개 제한상 불가능해서’ 생긴 일이 아니다.

모든 조건을 덮는 예시와 인물의 말투를 잘 보여주는 예시는 같지 않다. d07·d08에도 `ordinary` 태그가 있어 태그상 일상 커버리지를 만족하지만, 실제 대화는 배려 설명과 약속 조율이 중심이다. 최종4개 중3개가 승인 선택 규칙을 보여주는 장면이어서 평범한 받아침·자기 이야기·장난이 상대적으로 약하다.

이 예시들이 실제 응답의 설명·협의 패턴을 유도했을 가능성이 높다. Google의 공식 안내도 예시가 표현·범위·응답 패턴을 유도하며, 짧은 답을 원하면 그에 맞는 예시를 보여 주도록 설명한다. 이 일반 원리는 이번 인과 효과를 실험으로 입증한 자료는 아니다. [Gemini 공식 프롬프트 안내](https://ai.google.dev/gemini-api/docs/prompting-strategies#zero-shot-vs-few-shot-prompts)

## 3. ‘실제 말투 주입’은 최종 모델에 대한 직접 주입이 아니었다

실제 전달은 다음과 같다.

```text
감사한 말투 조각20개 + 내용 뼈대
  → GPT 말투 작성기
  → 새로 쓴 캐릭터34발화
  → 규칙 커버리지로13발화 선택
  → 일반 말투 규칙 + 선택된 합성 예시
  → Gemini 실제 대화
```

말투 조각20개는 작성기의 `voice.examples[].styleView`에 전달됐다. 최종 조립은 `voice.rules`만 직접 사용하고 원문 styleView를 넣지 않는다. 실제 최종 본문에 원문20조각이 그대로 등장한 것은0개다. 원래 화자의 사실 유입을 막기 위한 중간 변환 자체가 잘못됐다는 뜻은 아니다. 원문 직복사 수가 말투 재현 점수인 것도 아니다.

문제는 이 여러 단계를 거친 뒤 **원래 표현의 호흡이 보존됐는지 별도로 판정하지 않았다**는 점이다. 최종 말투 규칙은 ‘짧은 반말’, ‘한두 마디와 필요한 설명’, ‘감정은 짧고 구체적으로’ 같은 범용 설명이다. 개인별 `voiceProfile`도 빠졌으므로 중간 변환에서 줄어든 말투를 복구할 정보가 약하다. ‘실제 예시를 렌더러에 줬다’를 ‘실제 대화에서 그 말투가 구현됐다’로 읽으면 안 된다.

## 4. 내용 뼈대 자체가 설명과 관계 협의를 많이 요구한다

최종 관계 예시 d12-a1은 사용자의 요구를 재진술하고, 자기 마음을 검토해 불확실함을 밝히고, 숙고 후 다시 이야기할지 묻게 설계됐다. d12-a2도 연애 합의와 연락 의무를 구분하고, 일요일 대화와 그전 연락 휴식을 제안하고, 긍정 답변의 약속이 아니라고 덧붙이게 했다.

렌더러에는 행동·사실·합의 상태를 보존하고 필수 내용을 삭제하지 말라는 지시가 있다. 따라서 끝에서 “짧고 자연스럽게”라고 하는 것만으로는 앞 단계의 여러 설명 행위를 충분히 줄이기 어렵다. 실제 최종 예시는 각각87자·111자였다. Gemini 관계 확답 답변은158자로 늘었으며, 요구 재진술→자기 상태 설명→다음 관계 방식 질문이라는 비슷한 구성을 보였다. 구성 유사성은 관측이며, 예시만의 영향인지는 대조가 필요하다.

더 작은 사례도 있다. ‘안전한 보행 구역’이라는 딱딱한 표현은 말투 작성기가 갑자기 만든 것이 아니라 d08/d11의 내용 뼈대에 이미 들어 있었다. 내용 뼈대 단계에서 관리 문장·설명 문장을 만들면 말투 단계가 그 구조를 그대로 보존하기 쉽다.

규칙 준수에 관한 세 구역(SYSTEM_RULES·CHOICES·KNOWS_AND_LIMITS)은 합계3279자로 전체6683자의 약49%다. 길이만으로 원인을 증명할 수는 없다. 특히 소유권·취소·동의 규칙은 이번 표본에서 유익했다. 제거보다 **내부에서 확인할 조건과 실제로 상대에게 설명할 내용의 구분**이 필요하다는 진단이다.

## 5. 관문과 평가가 성격 손실을 충분히 드러내지 못한다

현재 보존 검사는 행동·사실·주체·상태·분위기·새 주장·커버리지를 검토한다. `toneAppropriate`는 관계와 진지함에 맞는지를 보며, “기본 성격의 무뚝뚝함이 최종까지 살아 있는가”, “출처 말투와 비교해 설명이 얼마나 늘었는가”를 독립된 필수 항목으로 두지 않는다. 의미보존68턴PASS는 인물 고유의 말투 합격과 다르다.

이전 결론의 ‘장난기가 약하다’도 범위를 좁혀야 한다.42응답에서 장난기가 충분히 관측되지 않은 것은 맞지만, 평가 입력에는 이미 친해진 관계를 별도로 확립한 전용 장난 장면이 없다. 프롬프트도 장난을 친밀할 때로 제한한다. 이 결과만으로 친밀한 장면에서도 장난을 못 한다고 결론내릴 수 없다. 그럼에도 생성된 d06을 최종 예시에서 빼버린 선정 문제는 독립적으로 확인된다.

## 6. 수정 우선순위와 인과 확인

다음은 분석에 따른 제안이다. 이번에는 적용하거나 재호출하지 않았다.

1. **기본 성격과 개인별 말투 목표를 최종에 보존한다.** coreTraits·contrast·표현 강도 중 필요한 항목을 명확하게 전달하고, 추가 특질이 이를 대체하지 않도록 한다. 형용사를 넣는 데서 끝내지 않고 무뚝뚝함이 짧은 편들기로, 자존심이 자기 잘못이 없을 때 과하게 사과하지 않는 태도로 드러나도록 정의할 수 있다. 이는 향후 저작 해석이며 이미 검증된 성향 정의는 아니다.
2. **행동 커버리지와 말투 대표성을 함께 평가해 예시를 고른다.** 이번 d06 교체는 가능한 작은 시험이다. 실제 품질이 더 좋아진다고 아직 주장하지 않는다. 규칙 예시는 필요한 상태 전환을 보존하되 매 응답에 모든 설명을 요구하지 않도록 검토한다.
3. **말투 변환의 중간 결과와 최종 소비를 각각 검증한다.** 실제 원문의 개인 사실을 복사하지 않으면서도 짧은 받아침·질문을 생략하는 마무리·관계에 맞는 장난이 살아 있는지 확인한다. 진지한 장면에는 그 장면에 맞는 짧은 예시가 필요하다.
4. **한 변수씩 대조한다.** 현 프롬프트를 A로 고정하고, 기본 성격/말투 목표 보존만 바꾼 B, 예시 선택만 바꾼 C를 각각 비교한다. 둘 다 바꾼 D는 개별 효과를 확인한 뒤 살펴본다. 같은 실제 사용자 입력과 모델 조건을 쓰고 누적 대화와 고정 이력의 국소 비교를 구분한다. 사람 블라인드에서 인물성·자연스러움·선택 적합성을 따로 평가한다.

짧은 표현의 방향을 보여 주는 **미검증 저작 예시**로는 “너랑 얘기하는 건 좋아. 근데 사귈 마음인지는 아직 모르겠어.”가 있다. 현재 마음의 불확실함은 남기되, 질문을 되풀이하거나 관계 협상 전체를 한 답변에 설명하지 않는 방식이다. 모든 상황에 이 문장을 강제할 제안은 아니다.

특질·선택 설계 뒤 말투를 입히는 방향을 버릴 근거는 없다. 현재 확인된 문제는 **기본 성격의 전달 누락, 예시 선정 목적의 편향, 말투 변환 후 검증 부족**이다. 최종 출력 길이 제한이나 금지 문장 추가만으로 세 문제를 해결할 수 있다고 보지 않는다.
