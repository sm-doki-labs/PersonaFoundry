# 특질·선택·실제 말투 분리 구현

기준일: 2026-10-29. 사용자의 “계획대로 구현 진행해” 요청에 따라 [검토된 계획](../product/2026-10-29-persona-choice-voice-plan.md)의 Task 0~6을 구현했다. 새 프로필의 오프라인 구현·검증 결과다. 이번 작업에서 실제 페르소나 생성·대화 대조·학습은 실행하지 않았으며 기본 품질 판정은 **NOT_RUN**이다.

## 달라진 공정

1. S3에서 씨앗 요구를 먼저 분리하고 특질마다 우선순위·감수 비용·첫 행동·적용/비적용/전환 조건을 설계한다. 후보별 실제 같은 상황을 비교하고 다른 계열 검토자가 의미와 요구 충실도를 확인한다. 복수 후보는 G3에서 직접 선택해야 한다. 편집하면 원문과 대체 요구를 보존한 새 revision에서 다시 검토한다.
2. S7에서 승인 선택을 특질/blueprint에 고정한 뒤 12개 내용 뼈대를 만든다. 각 대화는 2~6쌍이고 두 대화 이상은 6쌍이다. 승인한 실제 말투 팩을 렌더러에 주고, 별도 검토자가 모든 턴의 선택·사실 소유자·조건·약속·의미 보존을 판정한다. FAIL/UNRESOLVED는 승인으로 넘어가지 않는다.
3. S8에서 일상·감정/관계·핵심 선택·조건 변경과 승인 규칙을 보여주는 4예시를 결정적으로 고른다. 커버리지가 부족하거나 8,000자를 넘으면 잘라서 숨기지 않는다. G6와 후속 소비는 정확한 기획·선택·말투·원문·검사·프롬프트 버전을 함께 검증한다.

말투 자료는 실제 파일/해시/인용·원본 대화·신뢰 승인 색인을 요구한다. 주입 예시와 검증 예시는 실제 원본 계보로 분리한다. 모델 초안을 실제 승인 자료로 취급하지 않으며 렌더러에는 원본 화자의 사건/전기를 넘기지 않는다. 생성 말투와 승인 말투의 기준이 섞이지 않도록 했다.

새 프로필은 `ko-text-choice-voice-long-v2`이며 opt-in이다. 기존 프로필·승인 결과는 유지한다. short와 학습 경로는 자동으로 만들지 않는다. [실행 안내](../guides/persona-quality-runbook.md), [말투 자산 안내](../guides/voice-assets.md), [설정 예시](../../factory.example.toml)를 따른다.

## 계획별 산출물

| 작업 | 구현과 확인 |
|---|---|
| Task 0 | PRD v1.7 FR-50~53 → spec v1.7 §17 → LLD v1.8 §15, 새 미동결 품질 프로필 |
| Task 1 | 요구·선택 근거·독립 의미 검토, 대상 명시 선택, 편집 후 새 revision 재승인, G3 근거 화면 |
| Task 2 | VoicePack/Binding, 실제 원본과 승인 색인 검증, 목표 적합성·비적용 조건·분리 감사 |
| Task 3 | 승인 선택 불변 blueprint-v2와 FormationBeats, 정본 출처·소유자·규칙 커버리지 |
| Task 4 | 내용 뼈대→말투 렌더러→턴별 의미 보존 검사, 첫 출력과 의미 실패 보존 |
| Task 5 | 커버리지 선정·bundle-v2·원천 해시·완료 단계 재개·G6/S9/S11 버전 검증 |
| Task 6 | 영속 공유 예산, 실제 생산자 자료와 소비 프롬프트 재현, A~D·별도 S8 비교 수집, S3 순서 진단·사람 검토 자료·실패 분모 |

A~D는 같은 시스템 지침·기존 컴파일 프로필을 사용한다. B/C/D는 선택과 blueprint, B/C는 생성 말투, C/D는 내용 뼈대를 공유한다. 소비 프롬프트가 선언한 producer와 실제로 일치하는지 다시 조립해 확인한다. S8 선정 대조는 동일한 12대사와 v2 조립 방식에서 CURRENT/COVERED만 바꾼다. S3 진단은 원래/예시 제거/순서 교환의 실제 입력과 첫 결과/실패를 감사하고 사람이 후보 위치별 행동을 분류한다. 이 도구들은 개발 지표만 내며 QUALIFIED를 출력하지 않는다.

## 검증

- 기준선은 654 passed·1 skipped, 최종 `bash scripts/check.sh`는 **729 passed·1 skipped**, 79.04초였다. lint·format도 통과했다.
- 건너뛴 1건은 별도 DB 환경이 없는 검사다. 기존 Starlette 경고 1건은 그대로 남았다.
- `node --check`로 G3 공통 화면 스크립트를 확인했다. 새 프로필의 실제 브라우저/모델 품질을 검증한 결과는 아니다.
- 합성 자료와 가짜 모델로 전체 S3→G3→S7→S8→G6·후속 소비, 실패·재개·출처/정책 변경·예산·평가 경계와 기존 v1 회귀를 확인했다.
- 로그는 `work/persona-choice-voice-implementation/final-check.log`, `final-build.log`, `wheel-check.json`에 있다.

독립 검토는 최초 5건과 후속 3건을 수정했고 [코드 검토 기록](2026-10-29-persona-choice-voice-code-review.md)에 재현·수정·재확인을 남겼다. 주요 반례는 무관한 원본으로 감사 통과, 오래된 정책으로 G6 승인, D를 C로 재표시, 부정형 말투 목표 오인, 완료 후 예산 상한 재개, 시스템 지침 차이, 빈 목표의 우회, 기존 S3 원본 출력 호환성이다.

배포 파일도 실제로 빌드하고 추출본을 저장소 밖에서 불러왔다. 프롬프트 36개와 런타임 자산 90개에 누락이 없었고 새 프로필·기본 규칙·생산자/진단 모듈을 읽었다. 기존 패키지 설정이 잘못된 키를 사용하고 Markdown 규칙 문서를 누락하던 문제를 함께 수정했다.

## 현재 한계와 다음 검증

코드 검사가 통과해도 일정 수준의 캐릭터 품질이 입증된 것은 아니다. 실제 기존 말투 자료의 승인·원본 계보·목표 적합성을 감사해야 하며, 임의로 사람 승인 기록을 만들지 않았다. 정확한 소비 모델 tokenizer, 고정 모델/추론/비용 상한, 사람 블라인드 검토, 독립 보류 세트가 있어야 정식 판정할 수 있다. 예시 수와 임계값은 제안 상태다.

새 프로필은 비용 상한을 입증할 수 있는 API 경로만 지원한다. 실제 Codex 중첩 도구 실행·공유 예산 밖 구형 subprocess 형성·의미 상태 분기는 명시적으로 거절한다. 동일한 중립 후속 질문으로 비교하며 기존 v1 경로는 유지한다. 실제 구형 모델 비교는 동결한 개발 산출물을 사용한다.

다음 실제 검증 순서는 기존 선택 장면의 첫 응답 확인 → S3 최소 진단 → A~D → 같은 12예시의 S8 선정 비교 → 누적 대화·정식 보류다. 실제 모델 호출은 이번 구현에 포함하지 않았다.

## 작업 보존

`codex/persona-quality-floor`에서 기존 미커밋 작업을 보존하고 시작 시 411파일 기준선 사본과 해시를 남겼다. `work/persona-choice-voice-implementation/`에 전체 검사·빌드·기준선 대비 diff·검증 결과를 저장했다. 다른 저장소·기존 실험 원문은 변경하지 않았으며 커밋·푸시·학습 제출은 하지 않았다.
