## 해석

- 공정은 설계대로 돌았다. 검사 실패 → 사유 포함 재생성, 정렬 검사의 거절, 중단 뒤 재개, 관문 대기(G6 `AWAITING_HUMAN`), 원장 기록이 모두 확인됐다.
- 특질 시트는 P29 카드의 판단 규칙·상황 규칙·경험을 "조건 → 행동 → 전환"으로 옮겼고, 선택 학습 5항목이 모두 서술됐다. 외모 정보는 입력에 없었으므로 D-0005 위반 가능성이 없었다.
- 표본 응답은 다섯 문장 모두에서 P29의 선택(멈춘 지점 찾기, 작은 행동 제안, 자기 몫 맡기, 반대 근거 묻기)이 나타났다. "그냥 들어 줘"에서는 제안을 멈추는 전환 조건이 작동했다.
- 판정 LONG 4:1은 5문장 표본이고 판정 모델 1개라 경향 이상으로 해석하지 않는다. 짧은 프롬프트는 설계대로 `shortAdopted=false`다.
- 판단 안 되는 것: 이 결과가 사람 검토에서 승인될지(G6 미결), 긴 대화에서의 일관성, 다른 프리셋·사용자가 쓴 기획서에서도 같은 품질이 나오는지.

## 비용과 시간

호출 37회(Opus 30, Sol 7). 에이전트 호출 평균 35~48초. 사람 검토 시간은 아직 0(G6 대기).

## 한계와 고친 것

- `openai_compat`: json_object 사용 시 'json' 문자열 보장.
- S7·S8 RUNNING 전이에 rev를 기록하도록 수정(재개가 올바른 폴더를 찾기 위해).
- 표본 출력 토큰 300 → 1500. 고정된 프롬프트 쌍에 표본만 다시 돌리는 `acf persona probe` 추가(JSON은 `prompt-probe-r<k>.json`으로 누적, HTML은 파생 뷰라 덮어씀).
- `stance`를 한 단어 라벨로 쓰는 카드 관행과 "낱말 나열" 검사가 충돌한다. 재생성 결과가 더 쓸모 있어 검사는 그대로 두었다.
- 기획서의 이름·나이·직업·챕터는 에이전트 창작이다. 승인 전에 사용자가 바꾸면 `pr2`로 다시 들여온다.
