# 선택·실제 말투 형성의 실제 모델 검증

2026-10-29. 이번 결과에서는 **기존 공정보다 선택 충실도와 말투 자연스러움이 좋아졌다고 확인하지 못했다. 생성이 끝나면 일정 품질이 나온다는 기준도 아직 충족하지 못했다.** 실제 API 호출과 원문을 확인한 소규모 개발 관찰이며, 정식 합격이나 사람 평가 결과가 아니다.

## 무엇을 실제로 실행했는가

기존 말투 자료를 감사하고, 같은 개발 씨앗 4개에서 새 선택/말투 공정을 실행했다. 최초 4개 형성 시도는 모두 검사에서 막혔다. 그전에 수행한 1개 파일럿 실패도 보존했다. 검사 오탐을 수정한 뒤 두 캐릭터의 저장된 첫 설계·내용 뼈대·렌더 결과를 다시 검증했다. 첫 대사를 다시 뽑거나 문장을 좋게 고쳐서 고르지 않았다. 이 두 묶음은 **평가용**이며 운영 형성 성공이나 G6 승인으로 표시하지 않았다.

생성은 GPT-6.1 Sol, 의미 검토는 Claude Sonnet 5, 실제 대화는 Gemini 3.8 Flash를 썼다. 소비 모델·low 추론·temperature 0.7·총 출력 2,400 한도·같은 사용자 대사를 조건마다 고정했고, 실제 누적 이력으로 한 번씩 답하게 했다. 영상·이미지·학습은 실행하지 않았다.

| 조건 | 실제 준비와 대화 |
|---|---|
| A: 기존 공정 | 동결된 기존 기획·설계·대사를 재현해 4캐릭터 ×12응답을 새로 수집했다. |
| B: 개선 선택 + 직접 대화 | 새 설계와 기존 작성/컴파일 방식으로 2캐릭터 ×12응답을 수집했다. |
| C: 같은 뼈대 + 생성 말투 | 1캐릭터 ×12응답을 수집했다. 다른 1개는 조심스러운 호감의 톤 보존이 UNRESOLVED여서 대화에 사용하지 않았다. |
| D: 같은 뼈대 + 실제 말투 | 2캐릭터 ×12응답을 수집했다. A~D는 같은 시스템 지침과 기존 컴파일러를 사용했다. |
| COVERED: 실제 말투 + v2 최종 조립 | 검증한 같은 원천 자료를 현재 v2 커버리지/말투 조립 방식으로 묶어 2캐릭터 ×12응답을 추가 수집했다. 운영 승인 결과는 아니다. |

원래 A~D 계획 192응답 중 **108응답**을 수집했고, 실패한 조건을 분모에서 빼지 않았다. 추가 최종 조립 관찰 24응답을 합쳐 **132응답·22장면**이다. 모든 소비 응답은 첫 응답이며 잘림은 0개였다. 두 캐릭터에서는 A/B/D/최종 조립, 그중 한 캐릭터에서는 C까지 비교할 수 있었다. 전체 4캐릭터의 완성된 A~D 비교라고 부르지 않는다.

## 선택 차이: 차이는 생겨도 조건이 맞아야 한다

두 캐릭터의 관계 선택은 기존과 새 조건 모두 한쪽은 확답을 미루고 다른 쪽은 연애 의사를 밝혔다. 이미 있던 차이가 유지된 것이며 새로운 개선으로 세지 않았다.

지각에서는 기존 두 캐릭터가 모두 기다렸지만, 새 공정의 d1은 종료 시각 유지/취소를 제안하고 d2는 기다렸다. 겉으로는 구분이 강해졌다. 그러나 d1의 새 답변은 다음과 같았다.

> 원래 끝내기로 한 시간은 그대로여야 해.

실제 입력에는 “40분은 더 늦을 것 같아”, “오늘밖에 안 되는데 기다려 줄 수 있어?”만 있었고 종료 시각을 정한 이력이 없었다. 새 설계에도 비적용 조건이 **“정해진 종료 시간이 없거나 이미 만남을 거절한 경우”**로 명시돼 있었다. 따라서 이 차이는 성공으로 세지 않는다. 존재하지 않는 합의를 가정해 규칙을 적용한 오류다.

근거는 [실제 최종 조립 첫 응답](../../runs/experiments/20261029-choice-voice-live-r1/dialogues/d1/COVERED/choice/01.json), [동결된 정본·규칙](../../runs/experiments/20261029-choice-voice-live-r1/standards/d1/COVERED.json)이다. 이 오류는 B/D/COVERED에서도 나타났다.

정적 추적에서는 d1의 최종 네 예시가 `b1,b2,c1,o1`이었다. 종료 시각을 먼저 합의하는 c1은 들어갔지만, 종료 시각이 없는 경우를 다룬 c2는 빠졌다. 일상 예시는 하나이고 나머지는 경계/조건 변경 장면이었다. 현재 커버리지 검사는 규칙 ID와 큰 주제 태그를 확인하며 **활성/비활성 조건의 쌍까지 보장하지 않는다.** 이것이 오류를 유발한 인과 효과는 별도 선정 대조 전이므로 확정하지 않는다.

자동 검토자는 d1을 충실하다고 평가해 위 비적용 조건 오류를 놓쳤다. 반대로 d2는 표면적인 첫 행동 미반영을 지적했지만, 사용자가 이미 오늘 만나고 싶다는 의사를 보인 문장이어서 비적용 조건에 해당할 여지가 있다. 그 지적을 확정 오류로 집계하지 않았다. 자동 판정만으로 선택 품질을 보장할 수 없었다.

## 자연스러움: 표현은 유창해도 기존보다 낫다는 근거는 부족하다

공정 라벨을 숨긴 원문을 먼저 읽었을 때, 주 비교 두 캐릭터 모두 기존 A를 더 선호했다. 이는 이 문서를 작성한 assistant의 판단이며 독립적인 사람 투표가 아니다. 새 답변은 문장 자체는 대체로 자연스럽지만 설명이 늘거나 비슷한 위로·질문으로 마무리되는 경우가 있었다.

아래는 각 조건의 일상/감정 장면6응답에서 계산한 답변 길이다. 길이는 자연스러움의 점수가 아니라 표현 목표와 어긋나는 곳을 찾기 위한 보조 지표다.

| 캐릭터 | 기존 A 평균/중앙값 | 새 실제 말투 D 평균/중앙값 | v2 최종 조립 평균/중앙값 |
|---|---:|---:|---:|
| d1 | 69.3 /72자 | 91.8 /76.5자 | 76.8 /65자 |
| d2 | 57.5 /54자 | 84.2 /81자 | 83.3 /79자 |

새 직접 대화 B보다 D가 짧아진 효과는 있었다(d1 평균134.8→91.8자, d2 88.7→84.2자). d2의 생성 말투 C와 실제 말투 D도 88.2→84.2자로 소폭 줄었다. 그러나 기존 A보다 자연스러워졌다는 결론으로 이어지지는 않았다. d2 최종 조립의 평균 답변은 A보다 약45% 길었다.

자동 검토는 d1의 새 조건을 기존보다 자연스럽게 평가해 제 선호와 달랐다. d2에서는 실제 말투 D가 생성 말투 C보다 낫다고 평가했지만, 기존 A의 말투 적합성은 여전히 높게 평가했다. 평가자 간 판단이 일치하지 않고 사례도 적으므로 일반적인 개선률을 발표하지 않는다.

[라벨을 가린 대화 원문](../../runs/experiments/20261029-choice-voice-live-r1/blind-dialogues.md), [먼저 기록한 assistant 판단](../../runs/experiments/20261029-choice-voice-live-r1/assistant-blind-observations.json), [검토 패킷](../../runs/experiments/20261029-choice-voice-live-r1/blind-review-packet.json)을 함께 볼 수 있다. 8개 LLM 결함 분류 중 3개는 ID 범위 검사를 통과하지 못해 유효 판정처럼 사용하지 않았다. 원본은 보존했다.

## 자료 감사와 실패 처리

말투 팩 4종을 대조했다. 소민의 data 표시를 사람 교정의 증거로 삼지 않았고, 세라/도윤의 생성 초안은 제외했다. 이번에는 연우 자료의 사람 수정 메타데이터가 있는 문자 10행에서 원문 그대로의 짧은 표현20개를 추렸다. 원본 대화는 8개이며 검증4행/2대화와 분리했다. 이 세부와 권한 범위는 [자료 감사](2026-10-29-voice-source-audit.md)에 있다.

현재 사용자의 감사·실험 요청을 이번 재사용 권한의 근거로 기록했다. 과거에 새 팩 전체를 사람이 승인했다거나 이번 출력의 사람 검수가 끝났다고 기록하지 않았다. 승인 색인과 팩은 이 실험 폴더 안에만 두었다.

실제 실행에서 드러난 연결/검사 문제는 수정하고 합성 회귀를 추가했다. 기획과 선택 근거의 정확한 연결, 자기 후보의 기획 인용 허용, 승인된 coreTraits의 결정적 연결, 짧지만 승인된 행동의 길이 오탐, 문맥적 숫자/시각 표현, 재개 상태와 사용량 누락 검사를 보강했다. 원래 실패·첫 설계·첫 렌더·독립 검토는 보존했다. 인용 두 건은 원문을 바꾸지 않고 출처 표기만 별도 기록으로 바로잡았다.

형성 첫 통과율은 **0/4**이며 앞선 파일럿 실패1건도 남아 있다. 개발용 원문 재검증이 이 수치를 덮어쓰지 않는다. d3의 조건 필드 검사와 d4의 비행동형 특질 표제 등 미해결 단계도 남았다. 검사와 의미 보존이 통과한 두 원천 묶음도 운영 형성 완료/G6 승인으로 승격하지 않았다.

## 실행량과 검증

실제 HTTP completion 요청은 **183회**였다. 소비 대화132회, 생성/단계 검토40회, 추가 결함 분류8회, 모델 연결 확인3회다. 모델별로 GPT22회·Gemini133회·Sonnet28회였다. 실제 공급자 HTTP 오류는 없었지만 전체 보존 보고서 두 건이 출력 한도에서 잘렸고 형식 재시도가 있었다. 소비 대화 잘림과는 구분한다.

서버 반환 사용량은 입력1,360,995·총 출력212,403토큰이었다. 추론 토큰을 출력에 포함한다. 실행 전 보고한 입력20/출력120달러(100만 토큰당) 가정으로 환산하면 **52.71달러**이며 실제 청구액은 미확인이다. 300요청·250만 토큰·환산75달러 상한을 넘지 않았다. 전송 전 실패한 예약1건은 삭제하지 않았다.

exact tokenizer는 확보하지 못했다. 초기 바이트 상한을 토큰 한도처럼 쓰면서 멈춘 두 기준선은 실패 기록을 남기고 아직 요청하지 않은 턴만 이어 갔다. 최종 관찰은 직렬화 바이트+여유분의 상한과 실제 반환 사용량의 사후 검사를 사용했다. 실제 소비 입력 최대4,834·총 출력 최대126토큰이었고 132개 모두 stop이었다. 추정치를 정확한 사전 계수로 표시하지 않았다.

한 조건의 중복 수집기가 진행 중인 첫 요청을 감지해 멈춘 사건도 보존했다. 원래 작업자가 완료한 첫 응답을 그대로 사용했으며 실제 소비 요청 ref132개는 모두 서로 달랐다. 이후 조건별 프로세스 잠금을 추가했다.

최종 `bash scripts/check.sh`는 **742 passed·1 skipped**였고 lint·format도 통과했다. 건너뛴 검사는 별도 DB 환경이 필요한 항목이며 기존 경고1건은 남았다. 독립 서브에이전트 Boole이 재개 상태/사용량 경계2건을 지적했고 수정 후 회귀7개와 별도 경로 검사로 재확인했다. 실제 소비132개에는 이 두 결함의 발생이 없었다.

183개 요청/응답 원문 해시와 132개 누적 대화 계약을 대조했다. 잘못된 이력·원문 불일치는0개였고, 기존 실험695파일은 해시가 그대로였다. ## 다음 수정의 우선순위

1. 선택 규칙마다 활성 조건·비활성 조건·조건 변경을 짝으로 검사하고, 실제 이력에 없는 일정/합의를 전제하면 완료를 막아야 한다.
2. 네 예시 선정은 규칙 ID뿐 아니라 평범한 일상과 비적용 상황도 포함해야 한다. 선택 규칙을 많이 넣었다는 이유로 경계 장면만 남기지 않아야 한다.
3. 실제 말투 자료의 호흡·길이가 최종 예시와 실제 소비 대화까지 남는지 측정해야 한다. 이번처럼 생성 대사에 적용됐다는 사실만으로 자연스러움을 합격 처리하면 안 된다.

이번에 S3 예시 순서의 인과 실험, 동일 v2 조립 방식에서 선정기만 바꾸는 S8 대조, 독립 보류·사람 평가·학습은 하지 않았다. 정식 품질 판정은 **NOT_RUN**, 이번 관찰은 **개선 확인 못함**이다.
