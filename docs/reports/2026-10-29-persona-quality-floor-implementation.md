# 페르소나 형성 공정 구현·개발 관찰

**공정 기능은 구현했지만 기본 품질 보장 합격은 아직 아니다.** 개발용4캐릭터의 수정 공정은 모두 완성됐고, 별도 실제 대화24응답은 정상 종료했다. 독립 보류·기존/신규 대조·장기 대화·사람 블라인드 검토는 실행하지 않았다.

전체 원문은 [개발 관찰 HTML](http://127.0.0.1:8879/report.html)에 있다. 원본·요청·응답·실패·해시는 Git 제외 경로 `runs/experiments/20261029-quality-floor-development/`에 보존했다. 서버가 꺼지면 같은 폴더의 `report.html`을 열 수 있다.

## 구현한 것

- S7a는 특질과 상황별 행동·말투를 한 호출로 만들고, S7b는 정본 본문에서12개 다중 턴 예시를 만든다. 기획·특질·예시 허구의 출처와 소유자를 구분한다.
- S8은 모델 호출 없이 정본과 고정4예시를 long으로 조립한다. long8,000자 상한을 지키며 조용히 자르지 않는다. short는 미지원 상태를 명시한다.
- G6는 정확한 S7 revision·bundle·프롬프트를 승인한다. 다른 ID나 수정된 파일은 승인 전에 거절하고, S11은 승인된 persona-version과 같은 객체인지 재검사한다. 누락 파생 파일과 관문 상태는 저장된 bundle로 복구한다.
- 품질 명령과 첫 응답 원장·원문 해시·모델/설정 결합·전체 호출 예산·독립 사람 평가 양식을 구현했다. 자동 점수만으로 합격하지 않는다. 단가 미확인은 무료로 표시하지 않는다.

계약·실행 안내는 [실행 안내](../guides/persona-quality-runbook.md), 설계 근거는 [검토한 계획](../product/2026-10-29-persona-quality-floor-plan.md), 구현 계약은 PRD v1.6·spec v1.6 §16·LLD v1.7 §14에 있다.

## 원문에서 확인한 것과 남은 문제

정상 종료한 새24응답에서는 네 캐릭터가 자기 생활을 이야기했고, 조언 대신 들어 달라는 요청을 받았으며, 아직 합의하지 않은 일정의 변경을 잘못된 회상으로 거부하지 않았다. 같은 여정에서의 관찰이지 이전 공정보다 좋아졌다는 대조 결과는 아니다. 캐릭터에 따라 장난기와 자기 이야기 길이에 차이는 있지만, 공감 문구와 다음 질문은 비슷했다.

더 중요한 한계는 **S3 선택의 분화**다. 같은 기다림 상황에서 승인된 v1의 첫 행동이 아래처럼 모였다.

| 캐릭터 | 같은 기다림 상황에서 승인된 첫 행동 |
|---|---|
| d1 | 책을 꺼내 읽으며 기다리고 자기 독서에 시간을 쓴다. |
| d2 | 급히 오지 않아도 된다고 알리고 책 한 꼭지를 읽는다. |
| d3 | 기다릴 수 있는 시간을 알린 뒤 저장한 짧은 글을 연다. |
| d4 | 잡지를 펴고 도착하면 연락해 달라고 한다. |

생활 소재가 달라도 핵심 행동은 비슷하다. 한 상황만으로 모든 성격이 같다고 단정할 수는 없지만, 사용자가 요구한 “동일 상황에서 다른 선택”이 이 사례에서는 충분히 드러나지 않았다. 다음 개발 검증은 승인 기획뿐 아니라 씨앗의 우선순위→S3 충실도와 같은5상황의 행동 대조를 먼저 확인해야 한다. 프로필·자연 대화 예시를 만들었다는 사실만으로 기본 품질을 보장하지 않는다.

## 검토와 코드 검증

계약 검토 Lorentz/Zeno, 형성 구현 Sartre, 독립 검토 Bohr(평가)·Parfit(통합)를 활용했다. 독립 검토12건을 반영했다. 프로필 해시·중첩 출처·이중 평가·동결 임계값·정확한2회 분모·전체 예산·캐시 무결성·판정 재시도·승인 원본·중단 재개·ID 결합을 보완했고 해당 회귀 검사를 추가했다. 검토자의 초기 판정은 NOT READY였으며, 수정 후 통과 근거는 검사 결과다. 검토를 실제 품질 합격으로 바꾸어 기록하지 않았다.

`bash scripts/check.sh`는 lint·format 통과, **654 passed·1 skipped**였다. 최종 결과는 검증 기록에도 남겼다. DB 검사는 이번에 다시 실행하지 않았으며 skip을 유지한다. 실제 대화는 테스트 fixture로 옮기지 않았다.

## 호출·비용·다음 단계

실제 completion 요청은 **76회**다. 형성28회(성공 응답24회·HTTP400 4회), 관찰용 대화48회다. 판정 모델 호출·이미지/영상 실생성·학습 제출·배포·커밋은 없었다. 형성 전의 외모 준비는 가짜 공급자로 했다.

중계 보고값은 입력381,307토큰·보이는 출력129,224토큰·별도 reasoning14,979토큰이다. 중계의 total과 completion은 reasoning을 별도로 보여 주는 사례가 있어 실제 청구량으로 단정하지 않는다. 입력100만당 $1~10·보이는 출력 $5~50이라는 가정이면 약 $1.03~10.27이며 reasoning을 같은 출력 단가로 단순 더하면 약 $1.10~11.02다. 실제 단가와 청구 규칙을 확인한 비용이 아니다.

정식 검증의 정확한 tokenizer 연결은 아직 미확보다(`/v1/tokenize`404). 사람 검토·보류 분리·프로필 교정/동결도 남아 있으므로 `formalQualification=NOT_RUN`이다. 다음은 새 캐릭터를 더 뽑기보다 씨앗→S3의 우선순위와 같은 상황의 선택 차이를 확인하고, 계수·사람 평가 준비가 갖춰진 뒤 개발480응답·새 보류1,440응답을 실행하는 순서다.

후속 원인 분석은 [기획·선택·관찰 원인 분석](2026-10-29-persona-choice-cause-analysis.md)에 있다. 기다림 대응의 겹침은 후보 번호와 이번 선택 규약에 강하게 연결돼 있었고, 관계 확답의 차이는 남아 있었다. 모든 선택이 같아졌다는 해석으로 확대하지 않는다.
