# 에이전틱 실행: Planner가 고른 P29 캐릭터 「윤하린」 (2026-10-14)

## 질문

도구를 가진 에이전트(`codex_exec` 백엔드)와 오케스트레이터(`acf run --until G6`)로, 브리프 한 장에서 G6 검토 대기까지 명령 하나로 진행되는가. 같은 프리셋(P29)을 손으로 돌린 [첫 실행](2026-10-14-dohee-p29-persona-run.md)과 무엇이 다른가.

## 해석

- 손 실행과의 차이: 손 실행에서는 제가 프리셋 선택·기획서 작성·설정 수정·재개 명령을 했다. 이번에는 Planner가 프리셋 선택과 기획서를, Profiler가 검사 실패의 자가 수정을, 오케스트레이터가 단계 진행과 관문 처리를 맡았다. 사람 개입은 브리프 작성과 G6 검토뿐이다(G3는 실험 플래그).
- 에이전트의 자가 검사 루프가 실제로 작동했다. 손 실행에서 러너가 두 번 호출해 고친 `stance` 문제를, 이번에는 에이전트가 한 실행 안에서 고쳤다.
- 두 캐릭터 모두 P29의 선택 패턴(멈춘 지점 → 제안 → 자기 몫 → 반대 틈)이 응답에 드러난다. 판정 방향(손 실행 LONG 4:1, 이번 SHORT 4:1)은 5문장·판정자 1개라 의미를 두지 않는다.
- 판단 안 되는 것: G6에서 사람이 승인할지, 긴 대화 일관성, 다른 프리셋·브리프에서의 재현성.

## 비용과 시간

전체 약 3분 10초. codex 실행 3회가 대부분이다. 사람 시간 0(G6 대기).

## 한계

- G3 자동 승인은 실험 편의다. 운영 흐름에서는 쓰지 않는다.
- Codex가 사용자 환경의 스킬·지시문을 함께 읽어 입력 토큰이 크다(캐시로 상쇄). 격리된 `CODEX_HOME`을 쓰면 줄일 수 있다.
- 오염 탐지는 명령 문자열 기반이다. 프로세스 수준 격리는 Codex 샌드박스(workspace-write)에 기댄다.
- 운영 시스템 규칙 원문(Q-0006)은 여전히 내장 기본값이다.
