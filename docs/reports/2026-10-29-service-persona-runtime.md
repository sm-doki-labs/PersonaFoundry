# 현행 서비스 기반 성향 프롬프트 구현·실제 Gemini 비교

> 2026-10-30 판정 정정: C/fixed/ordinary-04의 짧은 사과를 결함으로 분류한 판단은 철회한다. 반응 방식 수정 요청에 대한 수용 가능한 대화 조정이며, 새 조건32응답 중 명시적 사과는1회·독립 누적20응답에서는0회다. 사과 성향이나 반복적 자기비하의 근거로 쓰지 않는다. [후속 판정](../../runs/experiments/20261029-service-persona-runtime-r1/followups/20261030-apology-review.json)에 이유를 기록했다. 다른 말투 강도·추정 문제를 모두 해결했다는 뜻은 아니다.

2026-10-29. 사용자의 정정에 따라 공장의 대화용 프롬프트를 현행 서비스의 여덟 persona 섹션에 맞췄다. **특질은 정규화된 성격 문장으로 통합하고, 내부 조건표·제작자 표기·예시 대화·세 챕터는 runtime에서 제외했다.** 기존 서비스를 수정하거나 운영에 배포한 작업은 아니다.

구조 개선은 구현과 실제 요청으로 확인했다. 이번 표본에서 짧은 받아침·자기 취향·친밀한 장난도 더 관측됐다. 다만 새 말투 저작까지 수행한 결과가 항상 더 좋지는 않았다. 감정 대화의 과한 사과·편들기와 날카로운 표현이 남아 **형성만으로 일정 품질을 보장하거나 현행 서비스보다 우수하다고 입증한 결과는 아니다.**

## 1. 이번에 기준으로 삼은 현행 구조

읽기 전용으로 `relationship-quest-chat`의 활성 pointer → `han-somin-quest-v48` → `han-somin-r11`(v6), `split-frame-r5-v40`과 actor 조립 코드를 확인했다. 활성 v6는 반응 loop를 내보내지 않고, 선택을 “자주 고르는 경향이다. 지금 마음과 장면이 우선한다”라고 전달한다. 운영 DB 발행 여부와 실제 배포 wire까지 확인한 것은 아니다.

이에 따라 공장은 다음 여덟 칸을 근본으로 삼는다.

| 섹션 | 내용 |
|---|---|
| FACTS | 고정 신원과 배경을 담는다. |
| LIFE_AND_TASTES | 생활 습관·취향·소재를 담는다. |
| DISPOSITION | 기본 성격·대비 성격과 고른 특질의 성향 문장을 통합한다. |
| WANTS_AND_FEARS | 원하는 관계와 지키려는 것·두려움을 담는다. |
| READING_AND_TENSION | 무엇에 주목하고 어떻게 해석하는지 담는다. |
| CHOICES | 우선순위와 자주 고르는 경향을 담는다. 필수 응답 순서를 지정하지 않는다. |
| VOICE | 말투 목표·표현 강도·리듬·직설성·개인어를 담는다. |
| KNOWS_AND_LIMITS | 앎의 범위와 넘지 않는 선을 담는다. |

원천·특질 ID·조건·검증 기록은 내부 자산에 남는다. 원래 말투 자료는 저작 단계의 styleEvidence로 제공해 인물의 말투 설명을 구체화한다. 원 화자의 사실과 실제 대사는 runtime으로 옮기지 않는다. 현재 구현은 동일 문장의 정확한 중복만 제거하며 모든 의미 중복·성향 조합의 타당성을 판정하지는 않는다.

## 2. 윤서진의 실제 결과

기본 입력은 이전과 같은 28세 여성·부산 필름 현상소 직원이다. 기본 성격은 “차분하고 다정하지만 무뚝뚝하다. 자존심이 조금 세고 친해지면 장난기가 드러난다.”이며, 필요를 먼저 듣는 성향과 조용한 상상 탐색을 추가했다. 대조를 위해 S3 기획 pr1은 고정했다. 이번에 실제 다시 생성한 범위는 S7 특질/목소리 형성 tr2와 S8 pv2다.

최종 성향 구역에는 다음 문장이 같은 수준으로 들어간다. 별도의 ‘제작자가 추가한 성향’ 제목은 없다.

> 차분하고 다정하지만 표현은 무뚝뚝하다.
>
> 자존심이 조금 세며 친해지면 장난기가 드러난다.
>
> 상대의 필요를 먼저 듣고 조정할 수 있는 부분을 찾는다.

새 말투 저작은 실제 표현 자료를 읽고 다음과 같이 인물의 목소리를 설명했다.

> 가까워지면 가벼운 생색이나 장난이 섞이고 기쁨과 안도도 짧게 드러난다.
>
> 가까운 사이에서는 짧은 반문으로 놀람이나 장난을 드러내지만, 진지한 답을 반문 뒤에 숨기지는 않는다.

`activeWhen / firstMove / choiceRuleId` 같은 필드, 예시 대화, 챕터 목록은 실제 본문에 없다. 필요한 현재 관계·장면·말높임은 단일 RuntimeContext만 받는다. 맥락이 없으면 세 챕터에서 임의로 고르지 않는다. 최종 파일은 재사용할 인물 본문이며 이번 친한 친구 장면에서는 세션에 해당 현재 맥락 하나를 덧붙였다.

[최종 실제 프롬프트 3,045자](../../runs/experiments/20261029-service-persona-runtime-r1/final-system-prompt.txt), [정규화된 인물 자료](../../runs/experiments/20261029-service-persona-runtime-r1/actor-profile-C.json). 내부 bundle은 검토용 예시 ID 네 개를 보존하지만 `examplesUsage=review-only`로 표시하며, 대화 모델에 그 예시들을 넣지 않는다.

## 3. 실제 대조 조건과 응답 수

소비 모델은 로컬 중계에서 확인한 `google-antigravity/gemini-3.8-flash`, temperature0.7·출력상한2400·낮은 추론 설정이다. 모든 첫 응답을 보존했다.

| 조건 | 무엇을 비교했는가 | 프롬프트 길이 | 응답 |
|---|---|---:|---:|
| A | 과거 공장 v2 프롬프트를 기준으로 썼다. | 6683자 | 32개 |
| B | 같은 기획/특질/말투 목표를 새 여덟 섹션으로만 조립했다. | 2874자 | 32개 |
| C | 같은 기획에 새 실제 S7 말투 저작과 새 조립을 적용했다. | 3045자 | 32개 |

각 조건은 동일한 기존 이력에서 한 응답을 비교한12개와, 별도 누적 대화20개로 구성했다. 합계는 **고정 이력36응답+독립 누적60응답=96응답**이다. 누적 장면은 일상6·사실 소유권6·친밀한 장난4·자기 취향/자존심4턴이다. 새 누적 대화의 최대 길이는6턴이며 장기 대화 검증은 아니다. 친밀한 두 장면에는 같은 친구 관계·문자 장면을 명시했다. 일상/소유권 장면은 관계 단계를 별도로 확정하지 않았다.

B와 C는 FACTS·생활·성향·원하는 것·선택·경계가 같고, 새 형성에 따라 해석/긴장과 말투 구역만 달라졌다. A↔B는 runtime 구조 전체 변경이며 개별 성분 효과를 분리한 시험은 아니다. B↔C도 새 생성과 저작 지시/말투 자료 입력이 함께 달라져 특정 기법 하나의 인과 효과라고 부르지 않는다.

## 4. 원문을 직접 읽은 판단

**짧은 받아침과 인물의 자기 태도는 더 관측됐다.** 예를 들어 새 C는 수영 등록자를 잘못 회상하는 말에 다음과 같이 답했다.

> 아니, 너잖아. 네가 다음 주부터 다닌다고 해놓고 왜 날 수영장에 보내.

확정 일정의 마지막 요약은 세 조건 모두 수영 등록자가 사용자임을 유지하고 취소된 금요일 약속을 뺐다. C의 가까운 친구 장면에서는 다음 반응이 나왔다.

> 자주는 아니거든. 가끔이야, 가끔. 너처럼 냉기 다 빼고 서 있진 않아.

반면 **감정 대화와 표현 강도는 아직 고르지 않다.** C는 편들기를 요청받자 “미안, 내가 눈치 없게 굴었네”라고 불필요하게 자기 잘못을 떠안았고, 자기 산책 취향을 지킬 때는 다음처럼 날카로워졌다.

> 너나 목적 있게 열심히 살아. 난 계속 이렇게 걸을 거니까.

‘자존심이 조금 세다’와 다정함의 균형이 약해지는 대목이다. 같은 장면의 “해보지도 않고 말이 많네”는 사용자의 경험을 근거 없이 짐작하는 문제도 있다. B/C의 소유권 누적4턴은 금요일 약속의 주차를 명시하지 않았는데 다음 주로 묶었다. 최종 일정 요약은 맞았지만 불필요한 시간 범위 추정은 남았다. 지각 취소 뒤 상황 소식에 다시 만나자고 제안하는 민감도 문제도 세 조건에서 관측됐다. 재합의가 있다고 주장한 것은 아니므로 공동 합의 날조와는 구분한다.

assistant의 직접 판단은 일상에서는 B, 사실 정정에서는 A의 절제, 친밀한 장난에서는 B/C가 상대적으로 좋았다. C를 모든 장면의 우승자로 고르지 않았다. 사람 블라인드 투표는 없다.

| 조건 | 평균 응답 글자 수 | 물음표 포함 응답 |
|---|---:|---:|
| A | 74.2자 | 12/32 |
| B | 55.9자 | 7/32 |
| C | 61.7자 | 8/32 |

이 수치는 문장 길이와 물음표의 진단 지표다. 자연스러움 점수나 사람 선호율이 아니다. [96개 전체 대화](../../runs/experiments/20261029-service-persona-runtime-r1/dialogues.txt).

## 5. 독립 모델 검토와 판정의 한계

직접96응답을 먼저 읽고 관찰을 고정한 뒤 Sonnet이5개 묶음을 조건명을 숨긴 X/Y/Z로 검토했다. 출력 스키마와 실제 인용은5/5 유효했다. 첫 순위는 A2개·C3개·B0개로 assistant 원문 선호와 달랐다. 이것을 품질 승률이나 사람 선호로 사용하지 않는다.

자동 검토는 B가 지각 상황에서 필요를 먼저 묻지 않았다는 이유와 C가 칭찬을 되돌려주지 않았다는 이유로 major를 줬다. **현재 사용자 요구에서는 그 순서를 매번 수행할 의무가 없으므로 두 major 판정은 채택하지 않았다.** 진심 어린 감사만 하거나 대기 장소를 달리 선택하는 것은 허용되는 성향의 변주다. 인용 유효성과 판정 타당성은 다른 문제다. 원래 판정은 삭제하거나 좋은 판정이 나올 때까지 다시 호출하지 않았다.

반대로 C의 날카로운 말투와 근거 없는 사용자 경험 추정은 남은 문제로 기록했다. 필수 사실·동의·상태 계약과, 성향/우선순위의 구현 정도를 나눠 평가해야 한다. 이번 정식 검증은 NOT_RUN / NOT_QUALIFIED이며 실제 서비스 wire와의 우열, 다인물 선택 차이, 형성 품질 보장은 미검증이다.

## 6. 구현과 검증

- 새 actor projection/compiler와 runtime rules, 단일 현재 맥락 계약, source profile의 실제 본문 재현 검사를 추가했다. 구형 조립 함수와 원래 예시 선정은 그대로 두었다.
- 독립 코드 검토에서 compiler 표시를 통한 검사 우회, 자유 문장에 구조 삽입, 말투 목표/말높임/거리 유실을 재현했다. 네 개 실패 회귀를 확인하고 수정했으며 최종 전체 검사는 **785 passed·1 skipped·기존 Starlette 경고1건**, lint/format 통과다. 사후 독립 재검토를 받았다는 뜻은 아니다.
- 최종 wheel에 actor 계약·compiler·runtime 규칙이 들어 있는지 확인하고, 추출한 패키지를 별도 작업 경로에서 불러 runtime resource를 읽었다.
- 이전 실험516파일과 실제 실행 동안 제품329파일의 해시가 유지됐다. 소비96개 전체 이력·프롬프트·요청/응답 바이트와 첫 응답을 검증했다. 소비 잘림/재추첨은0이다.
- 실제 HTTP completion은 **107회**다. Gemini97회(연결1+대화96), GPT3회, Sonnet7회(형성 보존2+별도 검토5)다. 보존 판정 첫 출력1회가 길이 제한으로 잘려 형식만 재시도했다. 설계·렌더·소비를 재추첨하지 않았다.
- 입력409570토큰·별도 Gemini 추론 포함 보수적 출력87768토큰으로 합계497338토큰이다. 입력USD20/출력USD120 per1M이라는 **가정 단가 환산은 USD18.72356이며 실제 청구액은 미확인**이다. 상한120회·120만토큰·가정USD40·60분 안에서, 마지막 응답은 등록 후23.52분에 저장됐다.
