# 공장 화면에서 실제 작업 실행하기

## 진행 화면(기본, D-0101)

`/studio/factory.html`이 실제 서버를 읽는 기본 진행 화면이다. 팀 묶음 그래프에 17단계의 순서와 지금 상태를 그리고, 사람이 할 일(실패, 관문 검토, 유료 실행 확인)을 맨 위에 모은다. 단계를 누르면 오른쪽에 시각·회차 이력·산출물 미리보기가 나오고, 검토하기를 누르면 오른쪽 시트에 기존 관문 화면이 열린다. 결정하면 검토 영역이 닫히고 무엇이 시작됐는지 알림이 남는다.

화면 이름은 Foundry(캐릭터 공장)이고 세 칸으로 나뉜다(D-0102). 왼쪽은 새 캐릭터, 받은 일 수, 캐릭터 목록(상태 점과 할 일 수), 화면 테마다. 가운데는 지금 할 일과 공정 그래프, 오른쪽은 고른 단계의 속성·미리보기·회차 이력이다. 검토하기를 누르면 오른쪽에서 검토 시트가 밀려 나오고, 그 안의 관문 화면도 같은 색으로 열린다. Escape나 바깥을 누르면 닫힌다.

- 화면 테마는 왼쪽 아래 세 버튼(시스템 설정 따르기, 밝은 화면, 어두운 화면)으로 바꾸고, 고른 값은 다음에 열어도 남는다.
- 창이 1440px보다 좁으면 왼쪽 칸이 아이콘 줄로 줄고, 1100px보다 좁으면 왼쪽 칸 대신 머리줄의 캐릭터 고르기 목록이 나오며 단계 정보가 공정 아래로 내려간다. 이때 테마 버튼은 보이지 않는다(K-0088).
- 관문 화면을 따로 열면(`/gate.html`) 기존 글래스 모양 그대로다.

캐릭터가 여럿이면 왼쪽 위 **전체 캐릭터**(`#all`)에서 캐릭터마다 사람 할 일, 지금 할 일과 대기 시간, 팀 8칸 진행 막대, 마지막 변화를 한 표로 본다(D-0103). 내 차례인 캐릭터가 위에 온다. **받은 일**(`#all/mine`)은 모든 캐릭터의 멈춤·검토·유료 확인을 모은 대기열이다. 검토 종류(예: 얼굴 고르기)로 거른 뒤 검토하기를 누르면 시트가 바로 열리고, 시트 머리나 결정 알림의 **다음 건**으로 같은 검토를 이어서 한다. 머리줄의 '전체 캐릭터'를 누르면 개요로 돌아온다.

- 공정 그래프는 화면에 맞춰 보인다. 오른쪽 위 막대로 축소·확대(75~200%)·맞춤을 하고, 확대했을 때만 끌거나 휠·화살표로 옮긴다. Ctrl/⌘+휠도 확대다. **크게 보기**는 왼쪽 탐색과 할 일을 접고 그래프를 넓히며 Esc로 돌아온다.
- 단계가 실패하면 할 일 맨 위에 쉬운 이유가 나오고, 원문은 오른쪽 '기술 정보'에 있다. 다시 실행은 그 단계부터 목표까지 이어서 돈다. 같은 단계가 두 번 넘게 실패하면 '오류 내용 복사'로 담당자에게 보낸다. 앞 단계가 끝났는데 도는 작업이 없으면 '이어서 실행'이 뜬다.
- 유료 단계는 '비용 확인'을 누르면 공급자와 예상 비용이 나오고, '유료로 실행'을 한 번 더 눌러야 돈다. 서버가 금액을 모르면 '견적 없음'이라고 적는다(K-0092).
- 반려는 확인 창이 한 번 더 뜬다. 고칠 부분만 바꾸려면 수정 요청을 쓴다.
- 평가·블라인드 20쌍은 위의 막대에서 고른 수를 보고, 1(A가 나아요)·2(B가 나아요)·3(비슷해요)으로 고르면 다음 쌍으로 넘어간다. N·P는 다음·이전 쌍이다. 20쌍을 모두 골라야 보낼 수 있고, 시트를 닫았다 열어도 같은 판이면 고른 값이 남는다.
- 관문 화면의 '기술 정보'에 보낼 답 미리 보기, 파일 목록, 결정 기록 원문이 있다. '메모 남기기'에 적은 이름은 다음에도 채워진다.
- 얼굴 고르기는 얼굴 10장(외모군 3~4개 × 2~3장)을 한 판에 보인다. 누르거나 숫자 키(1~0)로 고르면 오른쪽 결정 칸에 크게 보인다. 비슷한 얼굴은 ♡ 또는 S로 3장까지 추려 '나란히 비교'로 크게 놓고 고른다. 위의 외모군 칩으로 한 외모군만 볼 수 있다. 숫자 키는 시트 안을 한 번 누른 뒤 먹는다.
- 기획안 고르기는 후보를 열로, 같은 항목을 줄로 맞춘 비교표다. 안마다 다른 줄에 점이 붙고 '다른 항목만 보기'로 같은 줄을 접는다. 열 위의 '이 안 고르기'나 숫자 키로 고르고, 고칠 칸은 아래 '고른 안 고치기'를 연다.
- 챕터 배경 고르기는 한 줄이 한 챕터다. 후보 사진을 누르거나 숫자 키로 고르면 다음 챕터로 넘어가고, 마음에 드는 후보가 없으면 줄 끝 '직접 적기'에 한두 줄로 쓴다. N/P로 챕터를 옮긴다. 오른쪽 결정 칸에 챕터별로 고른 배경이 보이고, 모든 챕터를 골라야 '배경 N개로 확정'을 누를 수 있다.
- 장면·자세 고르기는 챕터 탭이다. 탭마다 장면 설명과 자세 후보를 같은 항목끼리 가로로 비교하고, 숫자 키로 고르거나 마지막 열에 직접 적는다. 고른 자세의 세부는 표 아래에서 고친다. N/P로 탭을 옮긴다.
- 완성 이미지 승인은 챕터마다 '괜찮아요'·'고칠게요'를 고른다. 이미지를 누르면 기준 얼굴과 나란히 크게 보고, ←/→로 챕터를 옮긴다. 고친 판에서는 지난 요청이 해당 챕터에 보이고 나머지는 미리 괜찮아요로 놓인다.
- 소개 영상 고르기는 첫 프레임 옆에 후보를 나란히 두고 '모두 재생'(Space)으로 함께 본다. 동작 영상 고르기는 줄이 동작, 열이 챕터인 표에서 칸을 열어 1로 쓰기, X로 빼기를 정한다. 챕터마다 하나 이상은 남겨야 확정된다. 다시 만들기를 요청하면 그때까지 정한 칸이 새 판에 미리 채워지고, '남은 칸 열기'로 다시 만든 칸부터 연다.
- 데이터 샘플·학습 데이터는 받은 편지함처럼 왼쪽 목록, 오른쪽 대화로 본다. 1·2·3으로 쓰기·고쳐 쓰기·버리기, J/K로 옮긴다. 데이터 샘플은 묶음마다 보내고, 보내면 다음 묶음으로 넘어간다.
- 패키지 승인은 출시 전 점검표다. 자동 점검을 확인하고 사람이 볼 항목 3개를 표시해야 승인할 수 있다.
- 모든 검토 화면에서 다음·이전은 J·K(또는 →·←), 주 버튼은 ⌘/Ctrl+Enter, ?는 그 화면 단축키 목록이다. 수정 요청·반려는 누른 뒤 5초 동안 '보내기 취소'로 되돌릴 수 있다. '보지 않고 첫 후보로 확정'은 아무것도 고르지 않았을 때만 보인다.
- 유료 단계의 '비용 확인'은 이번 실행 예상 비용(공장 설정 단가 기준)과 지금까지 쓴 비용을 나눠 보인다. 기다리는 유료 단계가 둘 이상이면 '함께 보기'로 합계를 보고 한 번에 실행한다.
- 결정하면 '방금 한 일'에 '다음 검토' 버튼이 나온다. 같은 캐릭터의 다른 검토를 먼저, 없으면 다른 캐릭터의 가장 오래 기다린 검토를 연다. 사이드바 아래 '사용 안내'에서 처음 할 일·용어·비용·막혔을 때를 본다.

- 캐릭터 이름 아래 **공정 | 모델 만들기** 탭으로 학습 경로(재료 → 데이터셋 → 학습 → 평가)를 따로 본다(D-0130, `#c/<id>/model`). 열면 진행 중인 단계가 먼저 보이고, 맨 위 '지금 할 일' 띠가 이 경로의 사람 할 일을 하나 보인다. 끝난 단계는 자물쇠가 붙은 읽기 전용이다. 학습은 '학습 시작'에서 예상 비용을 보고 한 번 더 눌러야 돈다. 도는 동안 진행 줄(감시 시작 → GPU 빌림 → 데이터 올림 → 학습 스텝 → 선별 답 → 결과 받기·반납 → 체크포인트 고르기), 추정 쓴 돈, 자동 반납 시각이 3초마다 바뀐다. '학습 중단'은 GPU를 반납하고 멈춘다. 결과를 받지 못해 GPU가 남으면 할 일 맨 위에 '다시 받아 오기'·'결과 버리고 반납'이 뜬다. '학습 없이 진행'을 고르면 평가에서 긴 프롬프트 채택을 확인한다. 웹 실행은 학습 계획을 세운 뒤 이 선택을 기다리며 평가를 먼저 열지 않는다.
- 캐릭터가 없으면 새 캐릭터 만들기 화면이 나온다. 등록은 실행하지 않는다. 등록 뒤 "어디까지 실행할까요"에서 목표를 고르면 이번 실행 범위·사람 검토·유료 확인 횟수와 결정 뒤 자동 재개 목표를 미리 보여 준다.
- 시각은 `ledger/stage-events.jsonl`(단계 전이)과 `ledger/gate-events.jsonl`(관문 열림·결정)에서 읽는다. 이 기록이 생기기 전(2026-11-07 이전)에 만든 캐릭터는 시각이 비어 있다.
- 외모 자료 없이 브리프만 등록한 캐릭터는 외모 갈래를 건너뛰지만, 시작 전 화면은 아직 이를 구분하지 못한다(K-0084).
- 이전 화면 `d-ops.html`(텍스트 공정 패널, 시연 모드)은 그대로 있고, 진행 화면 왼쪽 아래의 "이전 화면"으로 간다.

## 이전 화면(d-ops)

기존 글래스 시안의 기본 운영 화면은 실제 서버를 읽는다. 명시적 `?mode=demo`에서만 옛 시연 각본을 실행한다. 실제 화면은 서버가 없으면 오류를 표시하고 진행 상태를 만들어 채우지 않는다.

## 실행과 검수

1. 새 캐릭터 요청에 소문자·숫자·하이픈 slug와 브리프를 적는다. 요청 등록은 `creator-input/brief-r1.md`와 초기 `state.json`만 만들며 생성 호출을 하지 않는다. 같은 날 동일 slug는409다.
2. 요청을 선택하고 목표 관문을 지정한 뒤 시작한다. `POST /api/jobs`가 실제 작업 ID를 만들고 기존 `run_until`을 실행한다. 신규 브리프만 있는 요청은 기존 페르소나 우선 경로(S3→G3→S7→S8→G6)를 탄다. 외모 자료·순위 수집을 새로 구성하는 화면은 이번 연결 범위가 아니다.
3. 결재함에서 관문을 열면 상세 영역에 기존 관문 화면이 나타난다. 실제 후보와 자료를 읽고 선택·승인·수정 요청을 보낸다. 검토한 revision이 바뀌면409를 반환하므로 최신 자료를 다시 읽는다. 단계를 타이머로 완료하거나 사람 대신 자동 승인하지 않는다.
4. `auto_resume=true`이면 사람이 결정한 뒤 의존이 풀린 작업을 기존 실행기가 재개한다. `max_parallel` 범위 안에서 독립 갈래를 병렬 수행한다. `resume_until`은 서버 설정을 따른다. 최초 작업의 목표와 승인 후 재개 목표는 별개의 기존 실행기 설정이다.
5. 공급자에 `paid=true`가 설정된 단계는 실행 확인 대기로 남는다. 해당 단계의 실행 확인을 누르면 그 단계만 `confirm`에 넣어 요청한다. 학습 제출은 기존 별도 계약을 유지하며 화면 시작만으로 학습을 제출하지 않는다.

## 화면의 근거

공정과 의존관계는 `/api/runtime/graph`, 목록은 `/api/projects`, 선택한 캐릭터는 `/api/characters/{id}`에서 읽는다. 실행 이벤트 `/api/events`는 재조회 신호이며 재접속 뒤 snapshot으로 복원한다. 작업 큐의 `succeeded`는 이번 작업이 끝났다는 뜻이다. 사람 관문에서 멈춘 상태를 캐릭터 전체 완료로 표시하지 않는다.

작업대 상태·revision·관문·실패는 실제 기록을 쓴다. 단계별 진행률·예상 시간 등 서버에 없는 수치는 미집계로 남는다. 텍스트 자료·호출은 기존 제한된 원문 조회 API에서 읽으므로 전체 파일 탐색기는 아니다. 모델 설정 패널의 현재 배정과 과거 결과의 생성 출처를 구분한다.

현재 `character-factory-poc/runs/characters`만 사용한다. 과거 `agentic-character-factory`와 실험별 `factory` 루트는 복사하거나 합치지 않는다. 실제 루트에 캐릭터가 없으면 빈 목록이 정상이다. 취소·일시정지 API가 없으므로 실제 모드에서 해당 시연 버튼을 노출하지 않는다.

## 서버

서버는 요청 당시 종료 상태를 유지한다. 다시 열 때 공장 루트에서 다음을 실행한다.

```sh
uv run --locked python -m character_factory_poc.web --root /Users/johnhuh619/projects/character-factory-poc --jobs-dir work/studio-web-jobs-20261030 --port 8776 --log-level warning
```

진행 화면: `http://127.0.0.1:8776/studio/factory.html`.
이전 실제 화면: `http://127.0.0.1:8776/studio/d-ops.html`.
시연 화면: `http://127.0.0.1:8776/studio/d-ops.html?mode=demo#job/seoha-new/floor`.

설정 파일을 복제하지 않고 실제 `factory.toml`을 읽는다. `--jobs-dir`은 작업 큐 보관 위치만 분리한다. 여러 서버로 같은 캐릭터를 동시에 수정하는 운영은 지원 범위가 아니다.
