# 원문 기반 무예시 페르소나 공정

현행 표준은 **익준 pv6를 만든 evidence-v4**다(D-0180, 사용자 확정). 설정을 생략해도 이 경로를 사용한다. 예시 없는 8섹션·전체 생성용 원문 대조·팩트/조건 보존을 유지한다. `evidence-v5`는 명시적 실험용이고 기존 산출물은 보존한다. 아래 과거 경로 설명의 기본값은 현행 설정을 뜻하지 않는다.

원자 특징 검증은 `evidence-v3`로 선택한다. 실제 익준 검증에서 모든 후보가 보류되어 당시 기본값은 기존 `evidence-v2`로 유지했다. 새 공정을 품질 개선이 확인된 표준으로 승격하지 않았다. 아래 v2 설명은 과거 경로의 재현을 위한 것이다.

## evidence-v3

생성용 전체 허용 자료를 대화 단위로 미리 나눈다. 약 3/4는 발견과 조건 조정에, 1/4는 잠근 후보의 독립 확인에 사용한다. 기존 평가용 자료는 어느 저작 단계에도 넣지 않는다. 모든 메시지는 포함/제외 사유로 추적하고 원래 시간 공백·개인정보 경계를 유지한다.

화행을 먼저 구분하고 하나의 특징에는 하나의 언어 행동만 담는다. `response`, `continuation`, `closure`가 각각 현재 응답, 친구가 다시 받은 뒤의 반응, 현재 말차례 종료를 뜻한다. 적용 조건과 행동은 인용마다 별도로 판정한다. 부분 지지, 맥락 부족, 중복 구간의 상충 판정은 완전한 지지로 세지 않는다.

개발 자료에서 반례가 남으면 한 차례 범위를 좁히거나 후보를 버리고 모든 개발 구간을 다시 대조한다. 이후 잠근 후보를 확인용 자료에 대조한다. 확인 단계 이후에는 후보를 다시 쓰지 않는다. 개발 지지 2개 독립 대화·확인 지지 1개·잔여 반례 없음은 기계적 최소 조건이며 의미 품질 승인이 아니다. 입력 전체를 읽히지만 저장 인용은 제한하므로 수신/장난의 발생 확률을 계산하지 않는다.

최종 8섹션에는 해당 원자의 조건·행동·적용 경계를 그대로 넣는다. 독립적으로 확인되지 않은 다른 단계는 반응을 지시하지 않는다. 승인 사실표는 별도로 보존하고 원문 사건을 새 개인 기억으로 옮기지 않는다. 원문은 비공개 검토 기록에만 남기고 최종 예시 대사는 넣지 않는다.

분석 기본 호출의 최대치는 개발 묶음 D, 확인 묶음 V일 때 `3D+V+2`다. 범위 조정이 필요 없으면 `2D+V+1`이다. 형식 재시도는 revision 전체에서 최대 10회이며 실행 전 계획에 이 여유분까지 포함한다. 전송 오류의 수동 재개도 누적 실행 예산을 유지한다. 중단된 성공 응답은 요청/지시 해시와 독립 응답 파일 해시가 일치할 때 재사용한다. v3 기록에 응답 해시가 없으면 자동 재사용을 막는다. G6는 직접 근거 확인 후 승인해야 하며 새 후보가 기존판보다 좋아졌다는 판정은 별도 Gemini 비교로 한다.

# 원문 근거 기반 모티브 제작 공정

과거 evidence-v2 경로 설명이다. n8n 없이 공장 자체의 `cfp persona prompts`와 웹 만들기가 공유하는 경로에서 실행한다. 기존 revision을 덮어쓰지 않는다. `evidence-v1`은 과거 80개 표본 경로를 재현할 때만 명시한다.

## 흐름과 보장 범위

승인 원문 → 평가 자료 분리 → 생성용 전체 메시지의 포함/제외 확인 → 맥락을 보존한 구간별 관찰 → 조건부 특징 통합 → 모든 구간에서 특징별 지지·반례·정보 부족 대조 → 근거 부족/반례 후보 보류 → 조건을 보존한 무예시 8섹션 → G6 원문 직접 검토 → 시연·내보내기.

전체 자료를 의미적으로 정확히 이해했다는 보장은 모델 호출 완료로 생기지 않는다. coverage는 모든 허용 원문을 입력으로 전달했는지, auditCoverage는 모든 특징×구간의 분류 응답을 받았는지를 확인한다. 분류가 원문을 제대로 읽었는지는 G6 직접 검토에서 확인한다. 서로 다른 대화 두 개 이상의 지지는 필요조건이며 자동 품질 승인이 아니다. 반례가 있으면 현재 후보를 보류한다. 반례를 피하려고 조건을 바꾼 새 후보는 다시 검증해야 한다.

개인정보 표시, 링크·미디어 표식, 유효하지 않은 발화/시간, 초과 길이 말차례는 제외 이유와 ID를 남긴다. 제외된 메시지나 시간 단절을 건너뛰어 가짜 인접 대화를 만들지 않는다. 초기 본인 발화와 상대만 있는 구간도 포함하며, 인용 가능한 본인 발화 ID와 원문 복사 검사 범위를 구별한다. 평가용 본문은 추출·원문 대조 모델에 전달하지 않는다.

## 조건 보존

카드의 `trigger`, `first`, `shift`, `stop`, `limit`를 최종 프롬프트에 전부 넣는다. 별도 요약 `rule`은 v2 본문에 사용하지 않는다. 사실표는 그대로 보존하며, 자료가 없는 섹션은 부족하다고 남긴다. 확인되지 않은 과거·공동 기억은 긍정도 부정도 단정하지 않고 다른 일화로 메우지 않는다. 실제 대사·모범 답장·이전 문답 예시는 넣지 않는다.

## 설정과 실행

```toml
[stages.s8]
motif_compiler = "evidence-v2"
evidence_chunk_chars = 24000
# 호출별 크기 상한이며 전체 자료의 표본 상한이 아니다.
evidence_workers = 2
example_turns = 0
# evidence_scene = "인터뷰어의 질문에 원문에 맞는 말높임으로 답한다."
# evidence_scenes = { "캐릭터ID" = "친한 친구와 메신저로 이야기한다." }
```

장면은 원문 파일 형식과 별개다. 인물별 `evidence_scenes`가 공통 `evidence_scene`보다 우선하며, 없으면 기존 팬/가족 통화 선택을 따른다. 다른 인물의 장면 변경은 현재 인물의 검토를 무효화하지 않는다.

```sh
cfp persona prompts CHARACTER_ID
cfp persona prompts CHARACTER_ID --execute
```

기본 실행은 승인 원문에서 구간 수 N을 산정한 호출 계획을 보여 준다. 기본 분석은 구간별 관찰 N회·통합 1회·전체 대조 N회다. 형식 오류의 제한된 재시도, 추가 대화 표본, 상위 공정은 별도다. 예산 원장은 재시도도 포함한다. 실제 공급자는 공장 설정을 사용하며 Qwen으로 자동 교체하지 않는다.

구간별 성공 응답은 원천·지시의 정규화된 요청 해시와 함께 저장한다. 중단 후 완료된 구간을 다시 부르지 않는다. 실패 요청은 청구됐을 수 있으므로 예약을 유지하고 새 시도에 새 요청 ID를 사용한다. 형식 오류 응답은 별도로 보존하고 제한적으로 다시 요청한다. 시작 시의 수정 지시도 새 revision에 고정한다. 모든 구간이 끝나지 않으면 완료 처리하지 않는다.

## 검토·전달

S8에는 `evidence-coverage.json`, `evidence-chunks.json`, `evidence-observations.json`, `evidence-candidates.json`, `evidence-audits.json`, `evidence-decisions.json`, `evidence-review.json`, `evidence-packet.json`, `evidence-binding.json`, `analysis/`와 프롬프트 파일이 남는다. 이들은 원문이 포함된 내부 자료이며 공개 패키지에 원문을 싣지 않는다.

G6에서 원문·조건·지지·반례를 직접 확인한 뒤 승인한다. 자동 승인은 차단한다. CLI 승인 답에는 실제 검토자와 `evidenceReviewed: true`가 필요하다. 수정 요청·반려에는 확인란이 필요하지 않다. 승인 전에는 내부 검토용 응답만 만들 수 있고 일반 시연은 막힌다.

G6·시연은 원천 및 분석 산출물 해시를 확인한다. S11은 공개 표시를 추가하되 표준 본문을 조용히 변경하지 않으며, 원문 공개 검사와 충돌하면 멈춘다. 서비스 내보내기는 `persona/prompt-compiler.json`으로 버전을 확인하고 여덟 섹션을 그대로 전달한다. S7 추정 성격으로 다시 작성하지 않는다. 새 S8에는 새 시연 표본을 묶는다.

실제 품질·시연 모델의 응답·반복 실행 안정성은 별도로 검증한다. 오프라인 합성 테스트 통과를 인물다움의 합격으로 표시하지 않는다. 로컬 실행과 배포 서버 반영도 구별한다.


## 기능·말투 분리 경로 evidence-v4

`[stages.s8] motif_compiler="evidence-v4"`와 `example_turns=0`으로 실행한다. v4는 전체 허용 생성용 자료를 고정 분할하여 특징을 발견하고, 조건·대화 기능·언어 형식을 별도로 기록한다. 형태(어미·말높임), 통사(생략·절 연결), 담화(표지·수선), 어휘 사용역, 말차례 운영을 확인하며 원문 대사 예시를 프롬프트에 넣지 않는다.

각 후보의 응답 ID와 조건 인용 ID를 검사한다. 응답 이후 USER나 다른 SUBJECT의 문장을 잘못 인용한 항목은 `invalidItems`에 원본·사유와 함께 보존하고 지지·변이 집계에서 제외한다. 정상 항목까지 다시 뽑지 않는다. 형식상 전체 후보가 누락된 응답은 기존 공유 재시도 상한을 적용한다. 같은 응답의 상충 분류는 unclear이며 혼합 후보는 강제 행동이 아닌 조건부 경향으로 조립된다.

원문 조건과 실제 동기·낯섦이 같은지는 자동 인용 검사로 입증되지 않는다. G6 검토에서는 조건과 제외 조건이 응답을 보고 역으로 정의되지 않았는지, 원문 지지가 기능과 언어 형식 전체를 뒷받침하는지 확인한다. 생성 프롬프트의 조건 보존은 내용의 의미적 타당성 승인과 별개다. 비교 시에는 생성된 본문을 그대로 사용하고 실제 과거의 창작/부재 단정과 꼬리질문 대응을 각각 기록한다.

## 말투 사용 조건 표준 v5

`evidence-v5`는 명시적 실험용이다(D-0180). 명시한 기존 compiler는 계속 사용한다. 전체 생성용 원문에서 어휘 사용역·표현 강도·말차례 종료·표현 완화 조건을 구분하고 개발/확인 근거를 대조한다. `evidence-usage-coverage.json`과 G6 검토 JSON의 `usageCoverage`에서 각 축의 미관찰/근거 부족/검토 후보 상태를 확인한다. 한 축이 비었다고 예시나 상식으로 메우지 않는다. `conditionBasis`가 응답 역산 또는 불명확인 인용은 공동 지지에 들어가지 않는다.

검토 후보와 실제 품질 승인은 별개이며 기본 경로도 G6를 자동 승인하지 않는다. 예시 대사는 계속 금지하고, 현행 pv6는 고정한 `evidence-v4` 원문을 사용한다.
