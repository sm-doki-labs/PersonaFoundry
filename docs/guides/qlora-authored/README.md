## 창작 인물에서 달라지는 핵심 결정

1. 승인 정본을 데이터·평가의 유일한 정답 기준으로 둔다. 데이터 레코드와 평가 문항은 정본 revision과 해시를 기록하고, 정본이 바뀌면 영향받는 레코드 수와 전후 원문을 `prompt-policy-change.json`처럼 남긴다(소민은 642개 레코드의 system 문단을 한 번에 바꿨다).
2. 원천 발화가 없을 때 말투 기반은 승인된 기존 저작 대화, SNS 흐름 재작성, 합성 일상 대화 세 경로로만 만든다. SNS 원문은 흐름 참고로만 쓰고 원문 화자의 사실·대사·호칭을 옮기지 않으며, 10글자 이상 겹침 0을 기계 검사로 확인한다.
3. 사실 소유자 규칙을 공개 인물보다 정교하게 둔다. 자기 허구는 허용하고 유지 의무를 지우며, 사용자 사실과 공동 합의는 대화 근거가 있을 때만 쓴다. 이 규칙이 너무 넓으면 인물이 자기 일정조차 만들지 못한다는 것이 소민의 관측이다.
4. 상호작용 데이터를 별도 클러스터로 계획한다. 소민 r3는 답변 3,977개 중 1,803개(45.3%), 지도 토큰 109,157개 중 61,575개(56.4%)가 이력·주체·상황 대응·서운함 보강에서 나왔다.
5. 긴 대화를 명시적으로 만든다. 소민 r3의 15턴 이상 대화 37개와 15번째 이후 답변 242개는 모두 원본 SFT에서 왔고, 보강 대화는 최대 12턴이었다. 원본이 없는 새 인물은 긴 대화와 짧은 대화(1~4턴)를 따로 기획하지 않으면 두 꼬리가 모두 비게 된다.
6. 비율은 대화 수·답변 수·지도 토큰 세 분모로 보고하고, 대화 수 비율은 출처·보강 목적 비율로만 해석한다. 공장 D-0045의 56:8:22:7:7은 소민 r3의 대화 수 비율과 같으며 최적값이 아니다.
7. 평가는 고정 이력 문항, 자기 이력 연속 대화, 장기 대화를 섞고, 판정은 저작·생성과 다른 계열의 심사자 둘 이상과 순서 반전, 사람 블라인드 비교로 한다. 소민 평가는 대부분 저작자 Codex 한 명의 비블라인드 판정이었으므로 이 조건을 충족하지 못했다.
8. 소민의 미해결 행동(긴 문맥 뒤 성의 없는 사과 즉시 수용, 침묵에서 감정 주체 뒤바뀜, 잘못 없는 동반 사과, 무례가 이어질 때 관계 위협)은 합격 예시로 복제하지 않고 회귀 문항으로 고정한다.

## 창작 인물 정책

### 목표와 기준선

목표는 정본의 생활 기반·관계별 말투·상황별 선택을 짧은 system과 실제 이력만으로 200턴 안팎까지 유지하는 어댑터다. 학습 없이 긴 정본 프롬프트로 같은 품질이 나오면 학습하지 않는 결론도 정상 결과이며, 공장에는 이미 학습 없이 `LONG_BASE`로 패키지까지 가는 경로가 있다(D-0048).

현재 기준 사례는 소민 r3 3 epoch 어댑터다(`somin-r3-training-2026-10-22-r1/results/checkpoints/epoch-3`, sha256 `eaba1901…`, 출처는 `somin-longchat200-2026-10-23-r1/protocol.json`). 다만 이 후보는 같은 짧은 프롬프트의 기반 모델(B0)이나 긴 정본 프롬프트의 기반 모델(B1)과 같은 문항으로 비교한 기록을 찾지 못했다. 그래서 "어댑터가 강한 프롬프트보다 낫다"는 주장의 근거로는 쓰지 않는다.

### 데이터 정책

데이터는 [01-dataset.md](01-dataset.md)의 절차를 따른다. 클러스터는 말투·관계·일상 기반, 상황 대응, 이력 정확성, 주체·자기 일정, 서운함·갈등에 긴 대화를 더한 여섯 묶음을 제안한다. 각 묶음의 목표 비율은 [02-cluster-ratios.md](02-cluster-ratios.md) 8절의 제안값이고 허용 폭은 미정이다. 애교·이모티콘은 별도 클러스터로 두지 않고 관계·채널·감정에 따라 각 클러스터 안에 분포시킨다.

### 평가 프로필

| 프로필 | 목적 | 판단에 쓸 수 있는 범위 |
|---|---|---|
| persona_model | 고정 이력 문항으로 정본 사실·주체·자기 일정·서운함·말높임을 평가한다. | 어댑터와 체크포인트의 개발 후보 선택에 쓴다. |
| conflict_rollout | 자기 이력으로 8~14턴 갈등·사과·회복 대본을 진행한다. | 갈등 흐름의 개발 판단에 쓴다. 고정 이력 문항의 결과로 대체하지 않는다. |
| long_conversation | 자기 이력으로 90턴과 200턴을 진행하고 기억 탐침·반복률·갈등 유지를 본다. | 실행한 구성과 대본 범위의 장기 안정성 판단에 쓴다. |

검색·외부 조회를 쓰는 제품이 아니면 공통 규격의 grounded_product 프로필은 적용하지 않는다. 인물이 외부 조회를 할 수 없다는 사실을 지키는지는 persona_model의 정본 사실 문항에서 본다(차은결 개선에서 "불꽃놀이 시간을 검색해 주겠다"가 실패 유형으로 관측됐다, [소민 이전 보고서](../../reports/2026-10-29-somin-transfer.md)).

### 기존 평가 자료의 사용 범위

소민의 OE12·SE12·RL3·무례/사과 대본·200턴 대본은 체크포인트를 고를 때 이미 보았으므로 개발·회귀 자료다. 개발용 24문항은 r3 시점에 회귀 확인용으로 강등됐다. 독립 final_holdout은 소민에 없다. 새 인물은 정본을 고정한 뒤 개발에 쓰지 않은 장면 계보로 보류 세트를 만들고 한 번만 사용한다.

### 소민 기록의 상태 판정

공통 상태 모델로 옮기면 소민 r3 데이터는 manifest·해시·verification이 있어 `PACKAGE_FROZEN`에 해당하고, 학습은 어댑터 로드와 토큰 일치 확인이 있어 `CHECKPOINTS_RECEIVED`에 해당한다. 평가는 개발 자료와 단일 판정자로 이루어졌으므로 `DEVELOPMENT_EVALUATED`까지다. B1 대조가 없어 "학습이 프롬프트보다 낫다"는 질문의 결정값은 `INCONCLUSIVE`로 둔다. 3 epoch를 2 epoch보다 앞선 내부 후보로 둔 판단은 개발 수준의 선택으로만 기록한다. 이 판정은 이 문서의 제안이며 소민 프로젝트 문서의 기존 기록을 바꾸지 않는다.

## 미확인과 미정

- 원본 SFT 361대화의 작성 방식과 원천 대화 ID는 index에 `source_dialogue_id 미제공`으로 남아 있어 미확인이다. 그래서 원본 검증 61대화의 원천 독립성도 미확인이다.
- 2 epoch와 3 epoch의 사용자 블라인드 비교(17문항, `blind-2ep-vs-3ep/`)의 결과 기록은 찾지 못했다. 정답 키는 열지 않았다.
- 소민 r4(674대화, 긴 대화 30개 추가)는 학습하지 않은 후보다. r4의 긴 대화 보강이 장기 갈등 유지를 고치는지는 미확인이다.
- 클러스터 허용 폭, 축별 허용 퇴보 폭, 심사자 교정 합격선은 미정이다.
- 공장 `s9_data/plan.py`에는 턴 분포와 긴 대화 클러스터가 없다. 정책 초안을 코드에 넣는 구현은 이번 범위 밖이며 미구현이다.
- 이번 작업의 쓰기 범위가 이 폴더로 제한되어 [현재 상태](../../status/current-state.md)·인계 문서·결정 기록·문서 인덱스는 갱신하지 않았다.
