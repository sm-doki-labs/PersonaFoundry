## 1 시작 조건

창작 인물의 데이터 작업은 공장 G6에서 정본 프롬프트 쌍이 승인된 뒤 S9에서 시작한다. 공장 `s9_data/plan.py`의 `load_prompt_pair`는 G6가 `APPROVED`가 아니면 계획을 만들지 않는다. 공통 규격의 `GOAL_DEFINED` 상태는 창작 인물에서 "정본이 승인되고 행동 기준표·말투 규칙표·다듬은 예시가 정본 revision에 묶였다"는 뜻이다.

정본을 정답 기준으로 쓰기 위해 다음을 지킨다.

- core의 사실 문단에는 영구 설정만 넣고, 가족·병력·시간표처럼 나중에 대화와 충돌할 세부는 넣지 않는다.
- 성격은 형용사가 아니라 "이런 상황이면 이렇게 고른다"로 쓰고, 같은 상황에서 다른 인물과 달라지는 선택을 명시한다. 연우는 질투·성의 없는 사과의 선택이 정의되지 않아 블라인드 판별에서 소민으로 오인됐다(성의 없는 사과1 16개 중 14개, [세 캐릭터 비교](/Users/johnhuh619/Documents/Codex/2026-10-14/gem/outputs/charlong200-2026-10-26-r2/결과-보고서.md)).
- 데이터 전체의 system 문장을 바꾸는 정본 개정은 전후 원문과 바뀐 레코드 수를 남긴다. 소민 r3는 사실 규칙 문단을 바꾸며 642개 레코드에 적용했고 `R3/prompt-policy-change.json`에 기록했다.
- 학습 데이터와 평가 입력의 system은 같은 정본 문장으로 맞춘다. 긴 system으로 학습하고 짧은 system으로 평가한 소민의 초기 실행은 프롬프트 효과와 학습 효과를 분리하지 못했다(구축 가이드 3.4절).
- 정본에 없는 배경·성별·말투 예시를 추측해 정본으로 만들지 않는다. 공장은 승인 기획의 신원·생활·말투 예시·챕터를 코드로 직접 보존한다(D-0054, [소민 이전 보고서](../../reports/2026-10-29-somin-transfer.md)).

## 3 원천 발화가 없을 때 말투 기반을 만든다

창작 인물에는 실제 발화가 없다. 그래서 말투 기반 클러스터(`base`)의 자료는 세 경로 중 하나로만 만들고, 레코드마다 경로와 변환 이력을 남긴다.

| 경로 | 소민 또는 다른 캐릭터의 실제 사례 | 기록할 것 |
|---|---|---|
| 승인된 기존 저작 대화 | 소민 r3의 `original_sft` 361대화는 gemini-sft-poc의 Gemini 3.1 Flash SFT 데이터를 짧은 system으로 바꾸고 맥락 오류만 고친 것이다. index에는 원본 파일·줄·해시와 `changed_messages`가 남아 있다. | 원본 파일과 원본 레코드 해시, 바뀐 메시지 위치, 현재 레코드 해시를 기록한다. 원천 대화 ID가 없으면 `group_coverage_note`에 미확인을 적는다. |
| SNS 흐름 재작성 | AI Hub 297 SNS 대화(621,057개)를 흐름 참고로 쓴다. 원문 화제가 새는 방식과 받아치는 방식만 가져오고 대사는 새로 쓴다. 세라·연우는 보강 장면마다 서로 다른 SNS 대화 하나를 `sns_basis`로 골랐다. | `sns_refs`(파일·줄·가져온 것), 원문과 10글자 이상 겹침 0, 이미 쓴 SNS 대화 제외 목록(세라·연우 시점 1,020개)을 기록한다. |
| 합성 일상 대화 | 내용 뼈대(act·facts·tone)를 먼저 만들고 말투 규칙표와 예시로 따로 렌더링한다. 한 모델에게 내용과 말투를 함께 쓰게 하면 번역투와 상담원 말투가 나왔다. | `content_source`, 렌더러와 실제 모델 ID, `render_attempt`, `length_relaxed`, 한 줄 교정의 전후와 이유를 기록한다. |

공장의 S9 기본값도 같은 방향이다. `plan.py`의 `DEFAULT_MATERIALS`는 `base` 클러스터에 `SNS_REWRITE`와 `SYNTH`를, 나머지 클러스터에 `SYNTH`를 지정하고, `NIKL`은 접근 경로가 정해질 때까지 비활성이다. D-0045는 "원본 없는 캐릭터의 말투 기반은 SNS 재작성과 합성 일상 대화로 채운다"고 적었고 상태는 `제안`이다.

자료 기원은 공통 규격 2절의 두 축으로 기록하되, 근거의 기원 값을 창작 인물용으로 바꾼다.

| 근거의 기원 | 뜻 |
|---|---|
| `authored_canon` | 승인 정본의 문장과 다듬은 예시다. 학습 대화가 아니라 기준 자산이다. |
| `legacy_authored_sft` | 이전에 승인된 저작 대화다. 소민의 `original_sft`가 여기에 해당한다. |
| `sns_flow_reference` | SNS 원문에서 흐름 뼈대만 가져와 새로 쓴 대화다. 원문 화자의 사실은 들어가지 않는다. |
| `synthetic_authored` | 장면 기획과 내용 뼈대에서 새로 만든 대화다. |
| `hypothetical_scenario` | 평가나 대조쌍을 위해 일부러 만든 가상 장면이다. |

리뷰 상태도 분리한다. 소민 r3의 `ownership_augmentation` 43개는 index에 `review_type: author_self_review`로 남아 있다. 공통 규격은 데이터 제작자가 자기 후보를 최종 의미 검수 완료로 승인하지 못하게 하므로, 창작 인물 규격에서는 저작자 자가 검수를 `pending_review`로 두고 다른 검토자의 확인 뒤 `accepted`로 바꾼다.

## 4 상호작용 데이터를 만든다

말투 기반만으로는 대화 중 특정 행동을 배우지 못한다. 소민은 실제 실패를 보고 보강을 하나씩 추가했고, r3 학습 세트의 상호작용 보강은 다음과 같다.

| 클러스터 | 학습 대화 / 답변 / 지도 토큰 | 가르친 행동 | 만든 계기 |
|---|---|---|---|
| 상황 대응(`argon_augmentation`) | 54 / 348 / 13,355 | 사실과 모름의 구분, 조건 반응, 자기 잘못 수습, 경청, 거절 수용을 다룬다. | 기존 309개를 상황별로 점검해 빈 상황을 찾았다([상황별 보강안](/Users/johnhuh619/Documents/Codex/2026-10-14/gem/outputs/somin-coverage-audit-2026-10-21/상황별-보강안.md)). |
| 이력 정확성(`history_augmentation`) | 144 / 876 / 30,311 | 맞는 회상과 틀린 회상 정정, 시간·장소 변경, 제공되지 않은 사실, 여러 조건 유지를 다룬다. | 프리필로 이력 문제를 덮으려다 없는 일정을 만드는 문제가 생겨, 이력을 messages 자체로 넣고 데이터로 보강했다. |
| 주체·자기 일정(`ownership_augmentation`) | 43 / 189 / 6,122 | 자기 일정의 생성과 유지, 사용자 사실, 주인 분리, 공동 합의와 취소 구분을 다룬다. | "없는 일정 만들지 마" 규칙이 소민 자신의 일정까지 막아 정책을 좁혔다. |
| 서운함·갈등(`sulk`) | 42 / 390 / 11,787 | 가벼운 삐짐, 진짜 서운함, 선 긋기, 소민 잘못, 억울한 탓, 사과 뒤 회복과 덜 풀림을 다룬다. | 90턴 시험에서 소민이 거의 화를 내지 않았다. |

네 클러스터를 합치면 학습 대화 644개 중 283개(43.9%), 답변 3,977개 중 1,803개(45.3%), 지도 토큰 109,157개 중 61,575개(56.4%)다. 머스크 회고는 같은 비교에서 머스크 초기 데이터를 593답변·최대 6턴으로 기록했다([회고](/Users/johnhuh619/Documents/Codex/2026-10-22/new-chat-2/outputs/musk_retrospective_20261101/REPORT_KO.md) 3절). 회고가 밝혔듯 이 차이는 상호작용 예시가 필요하다는 단서이며, 소민의 배합이 최적이라는 대조 학습 결과는 아니다.

상호작용 데이터를 만들 때는 다음 사실 소유자 규칙을 장면 기획·내용 뼈대·검수에 모두 적용한다.

- 인물은 정본과 충돌하지 않는 자기 일정·취향·현재 행동을 만들 수 있고, 만든 내용은 이후 턴에서 유지한다.
- 사용자 정보, 공동 과거, 합의는 대화 근거가 있을 때만 말한다.
- 누구의 일인지, 제안·확정·취소 중 무엇인지 구분하고, 변경은 해당 주체와 대상에만 반영한다.
- 잘못 되묻는 말은 앞선 사실로 바로잡되, 없던 과거 발언을 만들어 반박하지 않는다.
- 장면 기획의 `scene`에는 이미 확인된 사실만 넣고, 대화 중에 바뀔 조건은 메시지로 넣는다.

갈등 데이터는 결말을 섞는다. 소민 r3 학습 세트의 `sulk` 42개는 짧은 샘플 11개(유형 A·B·F·L 각 2개, R 3개), 싸움 흐름 13개(풀림 9, 덜 풀림 4), 기승전결 18개(풀림 9, 덜 풀림 6, 선 긋기 3)다. 이 값은 `train-index.jsonl`의 `sulk_meta`에서 셌다. 서운함 데이터가 없으면 무조건 풀리는 인물이 되고, "상대가 바뀌지 않을 때"의 패턴이 없으면 안 풀리거나 격해진다는 것이 소민의 관측이다(구축 가이드 12장). 그래서 담백한 거리 두기, 위협 없음, 진지한 사과에 대한 회복을 함께 넣는다.

## 5 긴 대화의 비중을 계획한다

소민 r3 학습 세트의 턴 분포는 대화마다 assistant 메시지 수를 세어 얻었다. 7턴 이상 대화는 150개, 10턴 이상은 84개, 15턴 이상은 37개이며 최대는 30턴이다. 10턴 이상 대화가 차지하는 지도 토큰은 30,835개로 전체의 28.2%다. 같은 지표를 `turn_mix.py`의 근사 토큰으로 잰 기존 문서 값은 27.6%다.

창작 인물에서 가장 중요한 관측은 긴 대화의 출처다. 15턴 이상 대화 37개와 15번째 이후에 놓인 답변 242개는 모두 `original_sft`에 있다. 8번째 이후 답변 728개 중에서도 578개(79.4%)가 원본에서 왔다. 보강 클러스터는 상황 대응 최대 12턴, 이력 5~8턴, 주체 4~7턴, 서운함 5~12턴이었다. 짧은 꼬리도 마찬가지로 1~4턴 대화 214개 중 182개(85.0%)가 원본이다. 원본이 없는 새 인물은 두 꼬리를 따로 만들어야 한다.

세라 r3·연우 r1은 5~9턴에 75~80%가 몰려 있었고, 200턴 평가에서 7개 대화 중 5개가 101~200턴 반복률 66~94%를 보였다. 같은 대본에서 소민 r3는 0%였다. 그 뒤 현행 방식 문서는 턴 비율 기준을 정했고, 세라 r5·연우 r3에 적용해 `turn_mix` 경고 0건을 만들었다. 이 기준은 사용 실적이 있는 제안이며 학습 효과 검증은 세라 r6·연우 r4의 200턴 반복률 0~2%로 일부 확인됐다([세 캐릭터 비교](/Users/johnhuh619/Documents/Codex/2026-10-14/gem/outputs/charlong200-2026-10-26-r2/결과-보고서.md)).

|---|---:|---:|
| 1~4 | 25~35% | 214 (33.2%) |
| 5~9 | 45~55% | 346 (53.7%) |
| 10~14 | 7~10% | 47 (7.3%) |
| 15~19 | 2~5% | 16 (2.5%) |
| 20~30 | 3~5% | 21 (3.3%) |

| 10턴 이상 대화의 지도 토큰 | 25~30% | 28.2% |

목표 열은 [현행 방식](/Users/johnhuh619/Documents/Codex/2026-10-14/gem/somin-qlora-project/docs/캐릭터-SFT-데이터셋-구축-현행.md) 11.1절의 값이다. 긴 대화는 턴 수만 늘리면 안 된다. 같은 문서 11.2절에 따라 15턴 이상 대화는 화제가 두 번 이상 바뀌고, 정한 약속은 상대가 묻거나 바뀔 때만 다시 꺼내고, 중간에 짧은 받아침이 섞이고, 마지막 턴이 약속 재확인으로 끝나지 않아야 한다. 재확인 턴은 5% 이하, 마지막 턴 재확인은 15% 이하, 마무리 상투구는 1.5% 이하를 목표로 하며 소민 r3는 3.7%·9.9%·1.1%였다.

SNS 297 core의 2인 대화는 화자별로 합쳐 길어야 20턴이므로 SNS 대화 하나로 15턴 이상 대화를 만들 수 없다. 흐름 조각 2~3개를 한 대화 안의 화제 전환으로 이어 기획하고, 15턴 넘는 장면은 장면 기획에서 문자 채널로 고정한다. 소민 r4는 이 방식으로 긴 대화 30개(소민 15~26턴, 답변 582개)를 만들어 15~19턴 4.9%, 20~30턴 5.0%가 됐지만 학습하지 않았다(`GEM/outputs/somin-final-sft-2026-10-26-r4/README.md`). 긴 대화의 후반에는 인물의 선택이 드러나는 계기 상황을 넣는다. r4는 15번째 이후 답변에 "자기 실수로 웃기기"가 0줄이고 서운함 계열이 12턴 이하에 몰렸다는 스캔 결과로 이 보강을 만들었다.

공장 `plan.py`의 `ClusterPlan`에는 턴 수 범위나 긴 대화 비중이 없다. 정책 초안은 이 차이를 `dataset.turnMix`와 `long` 클러스터로 메운다([policy-v1.json](policy-v1.json)).

## 6 표본 검수 뒤 확대한다

소민의 모든 보강은 같은 순서로 진행했다. 부족한 상황을 숫자로 찾고, 인계안을 쓰고, 12개만 먼저 만들어 사용자 검토를 받고, 피드백을 기준에 반영한 뒤 나머지를 만들었다. 실제 수량은 Argon 보강이 첫 12개에서 60개, 이력 보강이 승인 12개에 148개를 더한 160개, 주체 보강이 승인 12개에 36개를 더한 48개였다. 서운함은 짧은 샘플 12개를 승인받은 뒤 싸움 흐름 15개와 기승전결 20개는 뼈대를 먼저 승인받고 대사를 생성했다.

공장 기본값도 클러스터별 12개 샘플 → G7a 사람 검토 → 대량 작성이다(`plan.py`의 `sample_size=12`, D-0045, G7a는 `--auto-approve`를 받지 않는다는 D-0047). 공통 규격은 새 작업의 시작 표본을 24대화로 제안하고 고정 수보다 커버리지로 고르라고 한다. 창작 인물은 두 기준을 합쳐 다음처럼 운영한다.

- 클러스터별 12개를 기본 표본으로 두되, 모든 자료 경로(기존 저작·SNS 재작성·합성)와 변환 방식이 표본에 한 번 이상 들어가지 않으면 수를 늘린다.
- 표본에는 위험 유형을 일부러 넣는다. 창작 인물의 위험 유형은 사용자 사실 날조, 주인 혼동, 제안·확정·취소 혼동, 틀린 전제에 동조, 지나친 "모르겠어", 잘못 없는 동반 사과, 사과 반복·증명 요구, 관계 위협, 시작 장면 근거 누락, 상대 대사 대필이다(구축 가이드 9.1절).
- 표본에서 핵심 의미 변경이 나오면 같은 변환 규칙이 적용된 묶음 전체를 다시 검토하고, 반복되는 교정 패턴은 다음 버전 규칙표와 렌더러 검사에 넣는다.
- 한 줄 교정본은 모두 직접 읽는다. 주어를 빼며 주인까지 지운 교정본이 세라 r2.1에서 44줄 중 7줄, 연우에서 21줄 중 2줄 나왔다(현행 방식 4.6절).
- 사람 검토 범위를 기록한다. 세라·연우는 예시 20개, 첫 12개, 유형별 표본 수준만 사람이 읽었고 전체 대화는 사람이 읽지 않았다.

## 7 계보 단위로 분할한다

공통 규격 8절의 계보 분할을 따른다. 소민 r3는 index의 `split_group`을 분할 단위로 썼고 실제 구성은 다음과 같다.

| 구분 | 수량 | 분할 방식 |
|---|---|---|
| `original_sft` | 학습 361레코드, split_group 309개 | 원본 대화를 잘라 만든 조각(`SM001-s01`~`s03` 등)은 같은 그룹이다. 여러 레코드를 가진 그룹은 42개다. |
| `history_augmentation` | 학습 144레코드, 그룹 72개 | 그룹마다 대화 2개이며, 보강 검증으로 8개 그룹(16대화)을 묶음째 뺐다. |
| `argon_augmentation` | 학습 54, 그룹 54개 | 원본의 대조쌍 `PAIR-A`~`PAIR-H` 8쌍은 두 대화가 모두 학습에 있다. 보강 검증 6개는 쌍에 속하지 않는다. |
| `ownership_augmentation` | 학습 43, 그룹 42개 | 보강 검증으로 5개를 뺐다. |
| `sulk` | 학습 42, 그룹 42개 | 짧은 샘플·흐름·기승전결에서 고르게 5개를 뺐다. |
| 기존 검증 | 61대화·337답변·7,114 지도 토큰 | 이전 실험과 바이트 단위로 같은 파일이며 원본 SFT만 있다. |
| 보강 검증 | 32대화·203답변·7,044 지도 토큰 | 보강 유형마다 약 10%를 묶음째 뺐다. 모두 문자 대화다. |
| 평가 | OE12, SE12, RL3 | 학습·검증과 ID가 겹치지 않고, 서운함 평가 입력은 학습·검증 대사와 10글자 이상 겹침 0이다(`R3/verification.json`). |

창작 인물 규격은 소민의 방식을 유지하면서 다음 빈틈을 막는다.

- 대조쌍과 같은 뼈대의 변형은 `split_group`을 같게 둔다. 소민의 `argon_augmentation`은 쌍 정보를 `source_group`에만 두고 `split_group`은 대화별로 두었다. 이번에는 쌍이 모두 학습 쪽에 있어 충돌이 없었지만, 규칙으로는 쌍을 분할 단위로 삼는다.
- 원천 대화 ID가 없는 기존 저작 대화는 `semantic_independence_claim=false`로 표시한다. 소민 원본 index는 "원본 source_dialogue_id 미제공; 독립 화자/원천 그룹 분리를 입증하지 못함"을 기록했다.
- SNS 흐름은 인물 사이에서도 계보로 관리한다. 한 SNS 대화가 두 인물의 학습에 동시에 쓰이지 않게 사용 목록을 누적한다.
- 공통 규격의 자료 수준(`train`, `loss_validation`, `development_generation`, `quarantined_legacy`, `final_holdout`)을 따른다. 소민에는 `final_holdout`이 없으므로 새 인물은 정본 고정 뒤 별도 장면 계보로 만든다.

두 검증은 함께 읽는다. 원본 검증 오차는 그대로이고 보강 검증 오차만 내려가면 새 행동을 배우는 구간이고, 둘 다 오르면 과적합 신호다. 소민 r3는 1→2 epoch에서 원본 1.414→1.418, 보강 1.236→1.195였고, 2→3 epoch에서 원본 1.534, 보강 1.267로 함께 올랐다([r3 학습 결과](/Users/johnhuh619/Documents/Codex/2026-10-14/gem/outputs/somin-r3-training-2026-10-22-r1/결과-보고서.md)). 보강 검증이 없던 이전 실행은 이 판단을 할 수 없었다.

## 8 마스크와 토큰을 확인한다

공통 규격 9절을 따른다. 소민 r3는 모든 assistant 턴을 지도했다. `train-tokenized.jsonl`에서 `labels != -100` 구간 수를 세면 3,977개로 assistant 메시지 수와 같고, system과 user는 마스킹됐다. system은 loss에서 빠지지만 모든 지도 답변의 조건이 되므로 정본 개정은 데이터 revision으로 다룬다.

토큰과 라벨은 로컬에서 미리 만들고 학습 서버에서 다시 만든 결과와 해시로 대조한다. r3 학습은 학습 644·기존 검증 61의 토큰과 라벨이 로컬과 완전히 같았고, 직접 계산한 검증 오차가 학습기 값과 일치했다(1.5846 대 1.5843). 학습 입력 최대 길이는 r3가 1,939토큰으로 2,048 이하였고, r4와 공장 기본값은 4,096이다(`plan.py`의 `max_length_tokens`). 소민 90턴 평가는 학습 최장 2,048토큰의 약 2.2배인 4,400토큰까지, 200턴 평가는 9,892토큰까지 진행됐다.

## 9 데이터 패키지에 남길 기록

공통 규격 10절과 계약 양식의 `package_manifest`를 따른다. 소민 r3 패키지에는 `manifest.json`(파일별 바이트·sha256·줄 수, `split_seed`), `verification.json`(ID·그룹 겹침, 중복, 바이트 동일, 토큰 일치, 길이, 평가 세트 겹침), `prompt-policy-change.json`, `prompt-components.json`, 세트별 index가 있다. 창작 인물 패키지는 여기에 정본 revision과 해시, 자료 경로별 수량, `turnMix` 실측과 경고, 리뷰 상태별 수량, 사람이 읽은 범위를 더한다.

## 10 소민에서 물려받지 않을 것

사용자는 소민을 복제 대상이 아닌 기준 사례로 쓰고 미해결 문제는 물려받지 않도록 분리하라고 했다. 다음 행동은 학습 데이터의 합격 예시로 쓰지 않는다.

- 긴 일상 대화 뒤 성의 없는 사과를 바로 받아 주는 행동은 쓰지 않는다. 200턴 147턴에서 3ep 3/4, 2ep 4/4가 이렇게 했다.
- 침묵 상황에서 "아직 화났어?"처럼 감정 주체를 뒤바꾸는 행동은 쓰지 않는다.
- 사용자가 잘못했는데 함께 사과하는 행동은 쓰지 않는다.
- 사과 없는 무례가 이어질 때 "연락하지 마" 같은 관계 위협으로 끝내는 행동은 쓰지 않는다. 무례 대본에서 새 2ep·3ep 모두 6개 중 3개가 위협·단절로 끝났다.
- 소민 고유의 소재(합주·밴드·국밥)와 말버릇은 다른 인물의 정본이나 테스트 fixture로 옮기지 않는다.
