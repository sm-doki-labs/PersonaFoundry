버전 0.1 초안 · 2026-11-02 · 상태 `제안`. 표의 실측값은 이 문서 1절의 방법으로 2026-11-02에 직접 센 값이다. 추천 템플릿의 비율은 모두 제안이며 비율을 바꿔 비교한 학습 실험은 아직 없다.

## 1 센 방법

대상은 학습까지 끝난 소민 r3 데이터셋 `/Users/johnhuh619/Documents/Codex/2026-10-14/gem/outputs/somin-final-sft-2026-10-22-r3`이다. r3 학습 실행 폴더의 `train.jsonl`과 이 데이터셋의 `train.jsonl`은 sha256 `8c2c029e…`로 같다([소민 이전 보고서](../../reports/2026-10-29-somin-transfer.md)).

- 클러스터는 `train-index.jsonl`의 `family` 값으로 나눴다.
- 답변 수는 `train.jsonl`의 각 대화에서 `role == "assistant"`인 메시지를 셌고, 턴 수도 같은 값(대화당 인물 턴 수)이다.
- 지도 토큰은 `train-tokenized.jsonl`에서 `labels != -100`인 위치를 셌고, 입력 토큰은 `input_ids` 길이다.
- 관계와 채널은 각 대화의 system 문장에 `prompt-components.json`의 관계·채널 문장이 들어 있는지로 판별했다. `call`과 `video_call`은 문장이 같아 음성 통화 하나로 묶었다. 판별 합계는 `verification.json`의 `by_rel_channel`과 일치했다.
- 답변 길이는 assistant 메시지의 문자 수다.

실행한 스크립트의 핵심은 다음과 같다. 외부 패키지 없이 python3로 돌아간다.

```python
import json, collections, statistics
d = "/Users/johnhuh619/Documents/Codex/2026-10-14/gem/outputs/somin-final-sft-2026-10-22-r3"
idx = {json.loads(l)["id"]: json.loads(l) for l in open(f"{d}/train-index.jsonl")}
tok = {json.loads(l)["id"]: json.loads(l) for l in open(f"{d}/train-tokenized.jsonl")}
rows = collections.defaultdict(collections.Counter)
for line in open(f"{d}/train.jsonl"):
    r = json.loads(line)
    fam = idx[r["id"]]["family"]
    turns = sum(1 for m in r["messages"] if m["role"] == "assistant")
    sup = sum(1 for x in tok[r["id"]]["labels"] if x != -100)
    rows[fam].update(dlg=1, ans=turns, sup=sup, inp=len(tok[r["id"]]["input_ids"]),
                     ge7=turns >= 7, ge10=turns >= 10, ge15=turns >= 15)
```

`long`을 별도 클러스터로 둔 이유는 3절의 관측 때문이다. 소민은 원본이 긴 대화를 공급했지만 새 인물의 `base`는 SNS 재작성으로 만들어지고, SNS 대화 하나로는 15턴 이상을 만들 수 없다. 소민 r4가 긴 대화 30개를 별도 `long_augmentation`으로 만든 것도 같은 판단이다. `long`의 최소값 0.05만 문서 근거가 있고, 나머지 최소·최대는 미정이다.

비율과 함께 다음 보조 목표를 정책에 둔다.

- 턴 분포는 1~4턴 25~35%, 5~9턴 45~55%, 10~14턴 7~10%, 15~19턴 2~5%, 20~30턴 3~5%를 목표로 하고, 10턴 이상 대화의 지도 토큰을 25~30%로 맞춘다(현행 방식 11.1절).
- 1~4턴 대화는 `base`·`ownership`·`situation` 안에서 따로 배정한다. 소민은 이 구간의 85.0%가 원본이었다.
- 존댓말 관계와 음성 채널은 각 상호작용 클러스터에 최소 한 장면 이상 배정한다. 수량은 미정이다.
- 답변·지도 토큰 비중은 목표가 아니라 보고 항목이다. 대화 비중과 함께 `distribution_report`에 남긴다.
- 갈등 클러스터는 결말 유형(풀림·덜 풀림·선 긋기)과 짧은 샘플·흐름·기승전결 구조를 섞는다. 소민의 실측 구성은 01-dataset.md 4절에 있다.

## 9 비율 조정에서 핵심 사례를 보호하는 규칙

머스크 초기 데이터에서는 중요한 발췌 16개 중 15개가 비율 조정으로 빠졌다([근거와 적용 단계](/Users/johnhuh619/Documents/Codex/2026-10-27/new-chat/docs/qlora-quality-system/06-EVIDENCE_AND_ADOPTION_KO.md) 1절). 창작 인물은 다음 규칙으로 같은 실패를 막는다.

1. 표본 검수에서 사용자가 승인한 12개와 정본의 핵심 선택을 보여 주는 대화에는 `protected_anchor`를 붙이고, 리밸런싱 전후의 생존 ID 목록을 남긴다.
2. 비율이 목표를 넘으면 해당 클러스터 안에서 계보가 과대 대표된 그룹부터 줄인다. 보호 사례는 품질·권한·오염·오귀속 사유가 있을 때만 격리하고 사유를 기록한다.
3. 비율이 모자라면 기존 대화를 복제하지 않고 새 장면을 만든다. 가중 샘플링을 쓰면 생성 원본 수와 따로 기록한다.
4. 지표가 넘으면 전체 평균을 희석하지 않고 원인 묶음을 고친다. 세라 r4·연우 r2는 새 보강 120개로 재확인 평균만 낮췄고 원인 묶음은 그대로였다(현행 방식 11.3절).
5. 보강 검증 몫은 클러스터별 약 10%를 묶음째 빼되, 보호 사례의 대조쌍을 학습과 검증에 나누지 않는다.
6. `protected: true` 클러스터는 대화 수가 줄어도 표본 검수를 다시 받기 전까지 0으로 만들지 않는다. 클러스터를 통째로 빼는 결정은 결정 장부에 새 ID로 남긴다.
7. 비율 변경의 효과는 같은 평가 조건에서 따로 확인한다. 클러스터 내용 수정과 비율 변경을 한 revision에 섞으면 묶음 효과로만 해석한다.

## 10 미확인

- 비율을 바꿔 학습한 비교 실험이 없으므로 56:8:22:7:7이나 위 제안값이 더 낫다는 근거는 없다.
- 원본 SFT 361대화 안의 의미 장면 분포(위로·갈등·회상 비중)는 재분류하지 않아 미확인이다.
- `long` 클러스터를 넣은 소민 r4는 학습하지 않았으므로 긴 대화 보강의 효과는 미확인이다.
