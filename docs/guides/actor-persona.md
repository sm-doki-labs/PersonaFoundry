# 현행 서비스 기반 성향 프롬프트

특질은 성격 문장을 일관되게 만들기 위한 저작 단위다. 제작자는 기본 성격을 쓰고 추가 성향을 고른다. 공장은 이를 상세 성격과 말투로 확장하되, 실제 대화 모델에는 출처별 구분 없이 한 인물의 설명으로 전달한다.

현행 서비스 저장소의 v6와 같은 여덟 persona 섹션을 사용한다. 비교한 로컬 활성 자료는 `han-somin-quest-v48` → `han-somin-r11`과 `split-frame-r5-v40`이며 운영 DB 발행까지 확인한 뜻은 아니다.

| 섹션 | 담는 내용 |
|---|---|
| FACTS | 이름·나이·직업과 고정 배경을 담는다. |
| LIFE_AND_TASTES | 생활 습관·취향과 대화에서 나눌 소재를 담는다. |
| DISPOSITION | 기본 성격·대비 성격과 선택 특질의 성향 문장을 함께 담는다. |
| WANTS_AND_FEARS | 인물이 원하는 관계와 지키려는 것·두려움을 담는다. |
| READING_AND_TENSION | 무엇을 먼저 보고 어떻게 해석하는지 담는다. |
| CHOICES | 자주 고르는 우선순위와 선택 경향을 담는다. 현재 마음과 장면이 우선한다. |
| VOICE | 표현 강도·말투 목표·리듬·직설성·감정 변화와 개인어를 담는다. |
| KNOWS_AND_LIMITS | 아는 범위·넘지 않는 선과 사실/약속 상태의 경계를 담는다. |

추가 특질에는 별도 제목을 붙이지 않는다. 예를 들어 “상대의 필요를 먼저 듣고 조정할 수 있는 부분을 찾는다”는 기본 성격과 같은 성향 구역의 문장이다. traitId·출처·선택 여부는 내부 자료에 남고 실제 대화 본문에는 나오지 않는다. 현재 투영은 동일한 문장을 중복 제거한다. 서로 다른 문장의 의미 중복이나 모순을 모두 판정하는 기능은 아니다.

기획·blueprint의 조건표, 대화 예시, 여러 챕터의 관계 목표는 내부 저작/검증 자료다. runtime은 이를 통째로 직렬화하지 않는다. 필요한 현재 관계·장면·말높임은 단일 `RuntimeContext`로 전달한다. 맥락이 없으면 세 챕터에서 임의로 골라 넣지 않는다.

말투 자료는 특질 저작기에 styleView로 전달해 말투 목표를 구체화한다. 원 화자의 사건과 사실은 보내지 않는다. 저작·검토용 예시는 남지만 runtime 예시 주입은 하지 않는다. 의미 보존 검사와 실제 대화의 자연스러움은 별개로 확인한다.

내부 구현 식별자는 `actor-tendencies-compiler-v3`, 본문 투영 자산은 `actor-persona-v1`이다. bundle의 `examplesUsage=review-only`는 내부 selectedDialogueIds 4개가 대화 모델에 전달되는 예시가 아님을 뜻한다. 이전 `choice-voice-long-compiler-v2`는 과거 재현용으로 남아 있다. 두 경로를 compiler 표시만 바꿔 섞을 수 없다.

공통 규칙은 `actor-system-rules-v1.md`다. `[stages.s8] actor_system_rules_path`를 명시하면 별도 산문 규칙 파일을 사용할 수 있다. 다른 섹션을 끼워 넣은 규칙 파일이나 성격 문장은 본문 검증에서 거절한다. 기존 `system_rules_path`는 구형 조립 경로의 설정이다.

새 조립은 8,000자 상한을 넘으면 실패한다. 문장을 조용히 자르거나 예시/챕터를 다시 붙여 성공으로 처리하지 않는다. G6에서 실제 본문과 원천 투영을 검증하며, 승인·실제 모델 품질·정식 품질 합격은 서로 다른 상태다.
