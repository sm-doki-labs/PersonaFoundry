# 승인된 말투 자료를 연결하는 방법

`ko-text-choice-voice-long-v2`는 내용과 선택을 먼저 정하고, 검증한 말투 팩의 표현 예시를 적용한다. 실제 원문과 모델 초안은 구분한다. 이 안내는 자산 형식과 입력 방법이며, 현재 소민·세라·연우 자료의 재사용 승인을 새로 확정하는 문서가 아니다.

## 1. 자료와 승인 기록

원문은 Git 밖에 둔다. 예를 들면 아래처럼 관리한다.

```text
/data/voice-library/
  trusted-approvals.json
  policy.json
  soft/
    pack.json
    source.json
    approval.json
```

`pack.json`은 `contracts.voice.VoicePack`의 `voice-pack-v1` 계약을 따른다. 최소 20개의 예시와 별도 검증 예시를 포함한다. 각 주입 예시에는 상황·관계·감정·문자 채널, `styleView`, 실제 원본 파일/해시/필드 경로/인용, `sourceGroupId`, `originalConversationId`, 자료 종류가 필요하다. 자료 종류는 `human-edited`, `approved-data`, `model-draft`이며 마지막 종류는 실제 주입 경로에서 거절한다.

`styleView`는 원본의 표현을 참고할 부분이다. 원본 화자의 직업·일정·공동 기억·선택을 복사하도록 만드는 전기나 전체 대화를 넣지 않는다. 팩을 준비할 때 공통으로 정리하고 변환 버전을 남긴다. 원본 해시와 인용은 변환본의 출처를 확인하는 데 사용한다. 렌더러에는 원본 인용과 파일을 주지 않는다.

규칙에는 문장 호흡·어미·감정 표현과 사용하지 않을 조건을 적는다. 관계가 멀거나 진지한 장면에서도 같은 애교·장난을 강제하지 않는다. `validationExamples`도 실제 원본 파일·해시·필드 경로·인용·원본 대화 ID·자료 종류를 포함한다. 주입 예시와 원본 그룹이 달라야 하며 승인된 팩 내용에 포함된다.

승인 기록은 다음을 포함한다.

- `assetSha256`는 팩에서 `approvalFile`, `approvalSha256`를 제외한 정규화 본문의 해시다. 계산은 `stages.s3_plan.choice_design.body_hash`와 동일하다.
- `reviewer="user"`, `decision="APPROVE"`, `scope="voice-pack"`와 검수한 `sourceGroupIds`를 기록한다.
- 신뢰하는 승인 색인 `trusted-approvals.json`의 `approvals`에는 승인 기록의 경로와 실제 파일 SHA-256을 둔다. 경로는 색인을 기준으로 한다.

팩이 스스로 가리키는 승인 파일만으로는 승인 증거가 되지 않는다. 운영자가 신뢰하는 색인에도 같은 파일·해시가 있어야 한다. 실제 승인 없이 `reviewer=user`를 만들어 넣거나 과거의 `by=data` 표시만 옮기지 않는다. 기존 자료를 옮길 때에는 실제 교정 원본과 승인 근거를 먼저 감사한다.

로더는 원본의 실제 바이트 해시와 필드의 인용이 같은지도 확인한다. 원문이나 승인 파일이 바뀌면 재바인딩·새 revision이 필요하다.

## 2. 캐릭터와 팩의 연결

정책은 명시적인 캐릭터 배정 또는 말투 목표 조건으로 팩을 선택한다. 아래는 형식 예시다.

```json
{
  "assignments": {"character-id": "soft"},
  "targets": {
    "character-id": {
      "requiredTags": ["반말"],
      "forbiddenTags": ["존댓말"],
      "positiveTags": ["짧은"]
    }
  },
  "rules": [{"requires": ["짧은", "반말"], "packId": "soft"}],
  "defaultPackId": null
}
```

`targets`는 운영자가 확인한 말투 목표다. `requiredTags`는 팩이 모두 만족해야 하며 `forbiddenTags`와 팩 태그가 겹치면 거절한다. 부정·예외가 있는 자연어 목표는 부분 문자열로 해석하지 않고, 비어 있지 않은 필수·금지 태그를 담은 구조화 목표가 없으면 `VOICE_SOURCE_MISSING`으로 남긴다. 조건 규칙의 `requires`는 긍정 토큰과 대조한다. `doNotUseWhen`은 바인딩·렌더러·최종 프롬프트에 전달하며, 문자 채널 자체가 금지된 팩은 거절한다. 복잡한 관계별 적합성의 자동 의미 판정을 보장하는 기능은 아니다.

여러 버전이 같은 ID로 중복되거나 적합한 승인 자료가 없으면 `VOICE_SOURCE_MISSING`으로 남긴다. 행동 특질에서 말투를 임의로 유추하지 않는다. 생성한 새 말투 초안은 `DRAFT`로 보존할 수 있지만 실제 말투 경로의 완료로 표시하지 않는다.

말투 바인딩에는 원본 사건·전체 대사가 포함되지 않는다. 승인된 표현 기준과 정리한 예시만 생성 단계에 전달한다. 대사의 내용 권한은 승인된 선택과 뼈대에 있으며, 말투 자료의 수락/거절·취향·사실을 가져오면 보존 검사에서 실패해야 한다.

## 3. 검증 자료의 분리

`SplitManifest`는 원본 대화, 파생본, 장면 계보와 용도를 저장한다. 같은 원본의 다른 발췌나 재작성본은 다른 문장 ID만으로 독립 자료가 되지 않는다. 실제 파일·바이트 해시·발췌 필드·원본 대화 ID·인용을 팩 원본과 직접 대조하며 주입/검증 또는 개발/보류가 계보로 연결되면 합격하지 못한다.

공통 승인 팩을 여러 캐릭터에 재사용할 수 있다. 평가자는 주입하지 않은 참조와 새 장면을 보고 표현의 전이와 자연스러움을 판단한다. 같은 예시를 다시 잘 말하는 결과로 새 캐릭터의 기본 품질을 주장하지 않는다.
