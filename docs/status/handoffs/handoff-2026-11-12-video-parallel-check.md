# 720p 영상 병렬 생성 검증 — 2026-11-12

두 편 동시 생성이 공장 소유 Grok OAuth에서 성공했다. 기존 합성 공 사진과 프롬프트를 그대로 사용했다. 모델은 grok-imagine-video-1.5, 720p, 9:16, 요청 길이는 각각 2초, 첫·끝 프레임 지정, 오디오 끔이다. 두 편 모두 720×1280·24fps·49프레임으로 디코딩됐다.

| 측정 | 결과 |
|---|---|
| 요청 시각 차이 | 0.00051초 |
| 두 요청 접수 | 시작 후 0.81초 / 0.86초 |
| 전환 영상 다운로드 완료 | 시작 후 31.99초 |
| 루프 영상 다운로드 완료 | 시작 후 37.45초 |
| 첫 요청부터 두 편 다운로드 완료까지 | 37.40초 |
| 공개 단가 기준 추정 비용 | 합계 $0.60, 사전 고지 상한 $1 |

앞선 순차 시험의 수집 시간 합계는 62.91초였다. 이번 37.40초는 제출부터 다운로드까지이며, 앞선 수치는 제출 시간 제외다. 같은 모델·입력의 두 실행이지만 실행 시각이 다르고 각 1회뿐이므로 정확한 배속 보장이나 대량 생성 처리량으로 일반화하지 않는다. 5초 간격 조회가 포함된 관측 시간이다. 두 작업이 첫 다운로드 전에 모두 접수됐으며, 실제 서버 내부 GPU 스케줄은 관측하지 않았다. 청구 금액과 최대 동시 작업 수는 확인하지 않았다.

공식 문서도 병렬 영상 생성을 안내한다: https://docs.x.ai/developers/model-capabilities/video/generation#concurrent-requests
API 요청 속도 제한은 동시 생성 가능한 최대 작업 수와 구분한다. 공장 OAuth 계정의 한도를 API 등급 표에서 추정하지 않았다.

현재 S6 `_run`은 각 영상의 `_generate`(제출→수집)를 마친 뒤 다음 영상을 호출한다. 공급자 보호 장치의 기본 video 슬롯은 2지만, 그 설정만으로 단계 내부 요청이 병렬화되지는 않는다. 이번 검증은 작업별 별도 공장 어댑터 인스턴스를 두고 동시에 호출한 것으로, 실제 S6·프론트 공정을 병렬로 바꾼 것은 아니다. 이후 도입 시 동시 2건부터 시작하고 작업 ID 저장·조회 재개·공유 예산·실패 처리·결과 순서 보존을 검증해야 한다.

실행: `.venv/bin/python work/video720-parallel-test/run.py --execute`. 각 작업의 POST 시도를 먼저 기록해 재시도/중복 제출을 막았다. 작업별 JSON과 summary.json, 로그, mp4, 시작·끝 PNG를 같은 폴더에 저장했다. 기존 인물/채팅 데이터와 서버는 변경하지 않았다. 이번에는 기능 코드 변경·커밋·배포가 없다. 이전에 중단한 페르소나 공정 수정도 재개하지 않았다.
