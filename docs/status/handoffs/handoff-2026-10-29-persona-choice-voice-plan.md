- 사용자는 특질·선택 설계를 개선하고 내용 뼈대에 실제 말투 예시를 적용하는 계획과 서브에이전트 검토를 요청했다.
- [계획](../../product/2026-10-29-persona-choice-voice-plan.md)과 [검토 보고서](../../reports/2026-10-29-persona-choice-voice-plan-review.md)를 작성했다.
- 두 검토자의 12건을 반영했고 수정본에서 담당 지적의 반영을 재확인받았다.
- 제품 코드·기존 실험·다른 저장소는 수정하지 않았다. 실제 페르소나 생성·모델 대조·학습·커밋은 실행하지 않았다.
- 새 공정은 계획 상태이며 기존 기본 품질 판정은 NOT_RUN이다.

## 2. 이번 세션에서 한 일

- 현재 S3→S7→S8과 기존 `act/facts/tone`·말투 팩 제작 문서를 대조했다.
- 요구 목록→특질/선택 근거→승인→내용 뼈대→승인 말투 렌더링→보존 검사→커버리지 컴파일을 설계했다.
- 7개 구현 작업과 합성 회귀, A~D 개발 대조, 별도 S8/S3 진단, 정식 보류 연결을 작성했다.
- G3 편집·선택 번호 편향·파일 간 관계·원문 사실 유입·분기 교란·공유 예산·평가 독립성·검토 자료·재개 무효화를 독립 검토로 보완했다.
- 문서 인덱스·현재 상태·결정·알려진 문제를 갱신했다. 문서 검증 기록은 verification.md에 남긴다.

## 3. 결정

- D-0060은 사용자가 요청한 계획·검토 범위를 확정했다.
- D-0061은 새 opt-in 프로필·계약·말투 자산·대조 방식의 제안이다. 구체 수량과 임계값을 사용자 확정으로 표시하지 않았다.

## 4. 확인한 사실과 정정

- 현재 APPROVE는 첫 후보를 선택하고, 승인 기획 로더는 plan.json 중심이며 선택 의미·출처 sidecar를 검증하지 않는다.
- 현재 S7b는 대화를 직접 작성한다. 기존 외부 도구의 분리 렌더러가 공장에 이미 연결된 것은 아니다.
- 현재 분기는 부분 문자열이며, 예산은 Context마다 새로 생성되고 미확인 단가를 0으로 합산할 수 있다. 새 프로필에서는 이 경로를 그대로 재사용하지 않도록 계획했다. 이번에 코드를 고친 것은 아니다.
- 서브에이전트 검토에서 지정 범위의 새 치명적 모순이 없다는 확인은 계획 반영 수준이다. 기본 품질 합격이나 실행 성공이 아니다.

## 5. 미결

- K-0047의 정확한 tokenizer 바인딩과 정식 사람/보류 준비는 남아 있다.
- K-0048의 예시 앵커링 인과 효과와 실제 선택 구현은 미검증이다.
- K-0049는 승인 말투 팩·뼈대·렌더링 분리 경로가 현재 공장에 미구현임을 기록한다.
- 기존 말투 자료의 승인 증거·사용 범위·목표 적합성은 전수 감사 전이다. 새 질문 Q는 추가하지 않았다.

## 6. 다음 할 일

1. 사용자가 구현을 요청하면 계획 Task 0에서 PRD→spec→LLD, 새 프로필, 측정 규약을 고정한다. 기존 미커밋 작업과 기준선 원문은 보존한다.
2. Task 1의 요구·선택 계약과 Task 2의 말투 출처/바인딩부터 구현하고 합성 반례를 검사한다. 다른 저장소는 계속 읽기만 한다.
3. 실제 실행 요청 전에는 dry run만 만든다. 실행 요청이 있으면 exact tokenizer·말투 자산·공유 예산을 확인하고 호출/토큰/시간/비용 상한을 먼저 보고한다.
4. 기존 long의 선택 실행 확인→S3 최소 진단→A~D→S8→연속 대화→정식 보류 순서로 진행한다. 개발 대조를 정식 합격으로 표시하지 않는다.
