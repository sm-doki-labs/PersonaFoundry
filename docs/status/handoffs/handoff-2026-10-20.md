## 1. 지금 상태 한눈에

- S1 방향을 확정했다(D-0017): 이미지를 수집하지 않는다. 화제성 순위 목록의 이름을 텍스트 모델(Scout)이 외모 특징 태그로 바꾸고, 3명 이상이 공유하는 특징으로만 외모군을 만든다. 이름은 다음 단계 산출물·이미지 프롬프트에 넣지 않고, 닮음 여부는 거르지 않는다.
- PRD·명세·LLD를 v0.2로 올리고 S1 절을 고쳤다. 새 요구사항은 FR-35(이름 분리)·FR-36(미리보기)이다.
- S1 오프라인 골격을 구현했다: `acf ref run`, `acf run --ranking`, `acf gate import <id> G1`. 합성 순위 목록으로 G1 선택까지 테스트가 통과한다(34 passed).
- 실제 모델·실제 순위 목록으로는 실행하지 않았다. 실제 이미지 어댑터는 없다(가짜 단색 PNG만 있다, Q-0014).
- G6 검토 대기 중인 캐릭터 둘(2026-10-14 인계)은 그대로다.

- 문서: [PRD](../../product/prd.md) v0.2(FR-04~FR-09 개정, FR-35·FR-36 추가, 비목표·의존성·위험 갱신), [명세](../../architecture/spec.md) v0.2(§3·§5·§6·§7·§8·§11·§13·§14·§15.1), [LLD](../../architecture/lld.md) v0.2(§2~§5·§8.1·§9~§13), [AGENTS.md](../../../AGENTS.md) 규칙 한 줄, [양식 모음](../../templates/README.md)과 [순위 목록 예시](../../templates/popularity-ranking-example.json), `factory.example.toml`의 `[providers.image]`·`[stages.s1]`.

## 3. 결정

## 4. 확인한 사실과 정정

- 2026-10-14 인계 §6의 "M1(S1 레퍼런스: manual 폴더 import → 태깅 → 중복 제거 → 군집 → G1)"은 D-0017로 대체됐다. manual 폴더·지각 해시 중복 제거·비전 태깅 캐시는 만들지 않는다.
- 외모군 정렬은 목록 수를 먼저 본다. 그래서 합성 데이터에서는 두 목록에 걸친 외모군(백분위 중앙값 0.46)이 한 목록 안의 외모군(0.75)보다 앞에 온다. 의도한 규칙(LLD §8.1 report)이지만 실제 데이터에서 어색하면 정렬 키를 바꾼다.
- 코드의 공통 특징 기준은 "구성원 전체의 과반"이다. LLD 초안 문장("unknown이 아닌 값의 과반")을 코드에 맞춰 고쳤다.

## 6. 다음 할 일

1. 사용자가 실제 순위 목록 하나를 [예시](../../templates/popularity-ranking-example.json) 형식으로 옮겨 `runs/briefs/` 등 Git 밖에 두고, 비교 범위(Q-0002)를 채운다. `acf ref run x --new-slug <slug> --ranking <file>`로 호출 계획(dry run)을 확인한다.
2. Q-0014를 정해 실제 이미지 어댑터(`providers/`의 OpenAI 호환 images 호출)를 붙이고, 가짜 어댑터와 같은 테스트를 통과시킨다.
3. 사용자 지시 뒤 `--execute`로 실제 Scout(opencodex 중계)와 미리보기를 한 번 돌리고, 같은 목록으로 한 번 더 돌려 ARI·이름 유출 0건을 [보고서 양식](../../templates/report-template.md)으로 남긴다(J2, 명세 §15.1).
4. G1 선택 결과(`selected_cluster`)를 입력으로 S2(M2)를 시작한다.
5. 사용자가 원하면 `git init`과 첫 commit을 한다(요청 없이는 하지 않는다).
