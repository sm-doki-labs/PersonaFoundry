# 인계: QLoRA 실제 연결(D-0077)과 창작 인물 정책(D-0078)

## 지금 상태 한눈에

- 머스크 N3b에서 결과를 낸 QLoRA 방식을 공장 S10에 옮겼다. G7 데이터셋 → Vast GPU 임대 → 학습(0.5 epoch 체크포인트) → 같은 GPU의 선별 생성 → 회수 → 생성 결과로 체크포인트 선택 → GPU 삭제 → S10 평가(SHORT_GEMMA_SFT는 GPU 어댑터 서버) → G8 → S11 serving 기록까지 코드로 이어졌다.
- 한소민 실측으로 창작 인물 QLoRA 규격(docs/guides/qlora-authored/)을 쓰고, 정책 qlora-authored-policy-v1을 S9(6클러스터·턴 분포·보호 클러스터)와 S10 보고서(문항군 커버리지·결정 초안·개선 과제)에 넣었다.
- 모든 확인은 가짜 호스트·가짜 vastai·가짜 모델로 한 오프라인 시험이다. 실제 GPU·판정 모델 호출은 0회다. 전체 시험 1048 passed, 1 skipped.

## 이번 세션에서 한 일

사용자 요청은 "최근 qlora를 공장 파이프라인에 적용해서 전체 플로우를 이어 보자", 중간에 QLoRA 품질 운영 규격 활용, 서브에이전트 병렬, 한소민 창작 인물 문서화와 시스템 반영이 더해졌다. 메인이 원격 학습·선별·서빙 스크립트, Vast 임대, 학습 공급자, drive·collect·CLI·설정·문서를 맡았고, 서브에이전트 아홉이 쓰기 범위를 나눠 체크포인트 선택(Ohm), GPU 평가(Erdos), 공급자·임대 시험과 버그 수정(Mencius), 패키지 serving(Wegener), 창작 인물 문서(Euclid), S9 정책(Schrodinger), S10 점수표(Halley), 독립 검토(Socrates)를 했다.

Mencius가 찾은 실제 버그는 세 가지다. 제출 명령이 ssh를 학습 끝까지 붙잡는 문제, 선별 시간 초과 때 상태가 계속 RUNNING인 문제, 결과 확인 전에 원격 폴더를 지우는 문제다. 메인은 Gemma만 학습할 때 짝 판정·지표·추천이 없는 SFT 조건을 찾다 멈추는 문제와, 선택 기록의 경로 접두어가 어댑터 경로를 깨는 문제를 고쳤다.

## 독립 검토와 수정

독립 검토(Socrates)가 유료 실행 전 P0 네 건을 찾았고 두 건은 가짜 Vast로 재현했다. 원격 스크립트가 Unsloth보다 trl을 먼저 불러오는 문제, 제출 중 실패 때 GPU가 남고 재실행이 두 번째 GPU를 빌리는 문제, 490MB 어댑터 회수가 120초 제한으로 실패하면 결과와 GPU를 함께 지우는 문제, 공장 밖 분리 감시가 없는 문제다. Descartes가 원격 스크립트(import 순서, 전 행 토큰·BOS·collator 확인, 선택 턴 지도, budget-partial, 선별 재시작 거절)를, Aquinas가 비용 안전(guard 분리 프로세스, 제출을 abort 구간 안으로, lease 기준 이어 가기, 회수 실패 시 GPU 보존, 전 revision·평가·라벨 정리, 신호 처리)을 고쳤다. 메인은 KEEP_INCUMBENT에도 어댑터가 채택되던 문제, 선택 실패 뒤 선택이 영영 건너뛰어지던 문제, 패키지 결정 대조, 사전 등록의 tr10/tr9 정렬을 고쳤다. 평가 GPU 세션의 guard 부재와 빈 답 처리는 K-0064로 남겼다.

## 결정

D-0077(QLoRA 실제 연결), D-0078(창작 인물 정책). 수치는 모두 제안이며 정책의 proposal 값은 운영 시작값이다.

## 확인한 사실과 정정

공장 S9 기본 56:8:22:7:7은 소민의 대화 수 비율이고, 답변·지도 토큰 분모에서는 다르다(서운함 6.5% → 답변 9.8% → 토큰 10.8%). 소민의 15턴 이상 대화는 모두 원본 SFT에서 왔으므로 원본 없는 새 인물에는 긴 대화 클러스터를 따로 둔다. 소민 평가는 블라인드·순서 반전·같은 프롬프트 대조군이 없어 학습이 프롬프트보다 낫다는 결론은 INCONCLUSIVE로 기록했다. 공장 Gemma 기본값은 이전 문서의 Gemma 2/3 응답 표시·linear·3 epoch에서 N3b 설정으로 바뀌었다.
