## 이번 세션에서 한 일

이전 세션은 연결을 설정/조회 패널로 좁혀 공장 본문을 시뮬레이터로 남겼다. 사용자가 상세 설명을 요청한 뒤 실제 로직 연결을 지시했으므로 이전 인계의 다음 할 일보다 이번 실행 연결을 우선했다. 시안의 `plans/2026-10-30-agentic-runtime-connection.md`에 계획표/API/작업 분담을 먼저 작성했다.

정확한 `opencode-go/deepseek-v4.1-flash` high를 명시한 CLI 작업자 A/B로 백엔드와 화면을 병렬 작성했다. A는 정상 완료했다. B는 runtime.js/.css·Node검사를 작성하고 자체 보완을 수행했으며 메인 통합 단계에 인수해 CLI를 종료했다(정상 완료 응답으로 집계하지 않음). 메인이 실제 API 스키마 정합성·갈래 배치·상세 창/키보드·문서·브라우저를 보완했다. 같은 모델의 별도 읽기 검토2회는 모두 완료했다.

백엔드 `web/runtime.py`는 STAGES와 기존 LANES를 읽는 그래프 API 및 `{slug,brief}` 등록 API를 제공한다. 브리프/state를 숨긴 임시 폴더에 완성하고 같은 slug의 파일 잠금 안에서 rename하여 불완전 요청이 목록에 보이지 않게 한다. 기존 캐릭터·revision을 덮어쓰지 않는다. JobManager 기본 러너는 고정 브리프를 매 실행/자동 재개 때 복원하고 state-v1 형식/subjectId를 검사한다. 등록 자체는 모델을 호출하지 않는다.

글래스 본문은 실제 그래프17단계·12관문·8갈래로 표시한다. 이전 가상 세부 작업·진행률·시간·비용은 실제 모드에 사용하지 않는다. 실제 기록에 없는 수치는 미집계다. 시작은 기존 POST /api/jobs, 검수는 drawer의 `/gate.html?...&embedded=1`에서 기존 모든 관문 UI/결정 API를 사용한다. 기본 설정에 auto_resume=true/max_parallel=3/resume_until=sx를 추가했다. 신규 브리프 요청은 기존 페르소나 우선 S3 draft 경로이며 외모 순위/얼굴 입력을 새로 구성한 기능은 아니다. 기존 외모 축 캐릭터는 기존 그래프를 따른다.

관문 결정은 잠금 안에서 최신 상태와 optional expectedRev를 검사한다. 검토하던 pr1 뒤 새 pr2가 생긴 화면은409로 거절한다. sourceGeneration과 selectedConfiguration은 기존 구분을 유지한다. 텍스트 패널의 작업실 링크와 라이브 헤더 탐색도 실제 화면을 가리키며 시안 작업실로 떨어지지 않는다.

## 독립 검토와 수정

초기 백엔드 검토는 프런트 파일 미완성·요청 생성의 불완전 폴더 노출·state 스키마 검증 누락을 찾았다. 파일 서빙/브라우저 확인, staging publish, 전체 계약/ID 검사로 보완했다. 프런트 검토는 jobId/id 불일치, 1280 그래프 축소, object 출력, 오래된 작업 URL, 시안 작업실 탐색, 폼 작성 중 목록 정지를 찾았다. 모두 코드·계약 검사·브라우저로 보완했다. 관문 매핑 누락 지적은 현행 그래프의12개 관문이 모두 실제 stage에 매핑되므로 재현되지 않았다. 검토 원문과 처리는 시안 `plans/runtime-work/`에 남았다.
