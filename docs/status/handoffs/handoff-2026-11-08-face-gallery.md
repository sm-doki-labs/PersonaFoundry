# 인계: 얼굴 고르기 갤러리(D-0105)

## 지금 상태 한눈에

- S1은 얼굴을 10장 목표로 외모군 순서대로 2~3장씩 만든다(4개 → 3·3·2·2, 3개 → 3·3·3). 같은 외모군 얼굴은 각도·표정만 다르다.
- G1 관문 화면은 갤러리 + 추려서 비교다. 결정 답 형식(얼굴 한 장)과 S2는 그대로다.
- 가짜 공급자로만 확인했다. 실제 이미지 호출 0회. commit/push 안 함.

## 이번 세션에서 한 일

사용자는 외모군 고르는 화면에 10장을 보이고 싶어 했고, 관문마다 화면을 따로 잡자고 했다. 시안 세 가지(갤러리·추려서 비교·크게 넘겨 보기)를 그렸고 사용자가 "갤러리로 가고 비슷한 얼굴은 추려서 비교하는 방식으로 해줘. 10장은 외모군 3~4개 × 2~3장으로 하고, 얼굴 고르기 화면부터 실제 관문에 적용해서 가짜 모델로 밝은·어두운 화면 확인해줘"로 정했다. 시안 원본은 대화 시각화 폴더(`g1-face-picker.html`)에 있다.

1. S1: `preview.py`(`face_counts`, 각도·표정 문장, 외모군별 장수), `run.py`(기본값·`preview_counts`·예산), `faces.py`(다시 만들기 배분).
2. 화면: `gate.js`(갤러리·칩·숫자 키·♡ 추리기·나란히 비교·결정 칸 크게 보기·기록 잠금), `gate.html`(`data-side-extra`), `gate.css`·`gate-foundry.css`.
3. `gate_items.py`: 얼굴 `variation`, 추천은 첫 얼굴만, 도움말.
4. 시험: 배분 규칙 시험 추가, 얼굴 장수 기대값 갱신(합성 외모군 3개 × 3장 = 9장).
5. 문서: D-0105, 명세 v1.19 §29, LLD v1.20 §27, 알려진 문제 K-0094, 검증 기록, 현재 상태, 공장 화면 안내.

## 확인한 사실과 정정

- G1 결정 기록은 고른 얼굴을 `referencePreviews`가 아니라 `selections`(외모군, 얼굴 순)에 남긴다. 기록 보기 화면은 둘 다 본다.
- 합성 순위 목록은 외모군 3개라 가짜 확인은 9장이다. 10장은 외모군 4개일 때 나온다.
- 진행 화면 시트를 연 직후 초점은 부모 창 닫기 버튼에 있다(접근성 규칙). 숫자 키는 시트 안을 한 번 누른 뒤 먹는다.
