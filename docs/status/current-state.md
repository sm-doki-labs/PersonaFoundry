## 4. 다음 할 일(우선순위)

- 서비스 기반 actor와 실제96응답을 기준으로 성향의 표현 강도·자연스러움과 사실 경계를 여러 인물에서 검증한다. 경향을 필수 절차로 오판한 자동 major2건은 채택하지 않았다(K-0055). 기존 예시 선정 강화안은 사용자 정정으로 runtime 적용 대상에서 제외했다. [새 실제 결과](../reports/2026-10-29-service-persona-runtime.md)를 따르며 현재 관계 명시·긴 누적 대화·사람 블라인드는 별도다.

- [실제 검증](../reports/2026-10-29-persona-choice-voice-live-validation.md)에서 개선을 확인하지 못했다. 다음 우선순위는 선택의 활성/비활성 조건 쌍과 실제 이력 없는 일정·합의의 차단, 일상/비적용 상황을 포함하는 예시 선정, 최종 소비까지의 말투 호흡 측정이다. 검사 통과만으로 새 기본값을 승격하지 않는다. 실제 대조와 형성 실패는 이미 기록했으며, 별도 보류·사람·정확 계수 검증은 여전히 남았다.

- 다음 텍스트 작업은 [원인 분석](../reports/2026-10-29-persona-choice-cause-analysis.md)의 최소 대조다. 이미 서로 다른 행동이 정의된 같은 관계 확답 상황에서 원래 long을 바꾸지 않고 첫 응답을 확인한다. 그다음 S3 예시 순서/제거 대조로 후보 번호 효과를 분리한다. K-0048은 상황 한정의 관측과 시험 편향으로 범위를 정정했으며 전반 선택 능력은 미검증이다. 정식 검증의 계수·사람/보류 준비는 별도로 남아 있다.

0. PoC(D-0044) 코드 범위는 끝났다. SFT 경로와 학습 없이 가는 경로(D-0048) 모두 합성 브리프로 S1 → G9 → 일회용 DB 적재까지 간다. 남은 PoC 항목은 사용자 지시 뒤 실제 공급자 1회 확인(순위 수집·이미지·LLM, P-24, Q-0022)이다. 실제 설정으로 한 캐릭터를 돌리면 학습 없이 진행을 골라 패키지까지 갈 수 있다.
1. 외모 한 번 고르기를 코드에 반영한다(LLD §12 M2b, K-0034): S1 외모군당 얼굴 1장, G1 얼굴 한 장 선택과 `cfp ref faces`, S2 기준 사진 + `identity-v1`(재생성 최대 3번), `base_photo = "picked"`, G2 제거와 `needs` 의존. 가짜 판정으로 통과·재시도·최종 실패·판정 없음 거절·picked 네 경로를 오프라인 테스트로 확인한다. 그다음 사용자 지시가 있으면 실제 이미지 공급자로 데모 G1 얼굴을 다시 만든다(K-0033).
2. 사용자가 데모 캐릭터의 G4 완성 이미지를 검토한다. 수정 요청이 있으면 챕터별 부분 재생성을 실제로 처음 써 본다.
3. 로컬 중계의 비전 입력을 확인하고(Q-0020), 판정과 사람 판단의 일치율을 잰다(K-0005, K-0007). 확인되면 이미지 자동 검사를 켜고 S4a·S4를 한 번 더 돌려 자동 검사를 L2로 올린다.
4. 영상 공급자 사용량(Q-0018)이 생기면 데모 캐릭터의 G4 승인 뒤 `cfp video actions <id>`로 계획(무표정 사진 3장 + 영상 18편)을 보고 `--execute`로 S6를 한 번 돌려 L2로 올린다(K-0029). 웹이면 `[stages.s6] resolution = "480p"`. 같은 사용량으로 S5도 G5까지 간다(K-0001). 그다음 특별 행동 제안 에이전트(K-0031).
5. 참고 자료 색인 재료와 임베딩 모델을 정한다(Q-0019, K-0004). 사람 선택이 들어간 실제 실행으로 기획·장면 노드의 L3 기준(변형 차이, 배경 다양성 K-0028)을 정한다.
