# OpenAI 공식 API 연결 계획

## 목적·범위

사용자 요청대로 기존 OpenAI 판정·비전 호출을 공식 `https://api.openai.com/v1`로 전환하고, 사진 생성은 구독 실행 대신 Images API로 연결한다. Gemini 텍스트 생성, Grok 영상, 기존 pv6/pv2·채팅·승인된 사진·영상은 보존한다. 사진의 기획 의존성 변경은 별도 작업이다.

## 방식

판정과 비전은 이미 공식 API 요청 형식을 지원하는 `openai_compat`를 재사용한다. 이미지 실험 클라이언트를 공급자 공용 코드로 옮기고 기존 import 호환성을 유지한다. 새 `openai_images` 어댑터는 참조 사진이 있으면 `/images/edits`, 없으면 `/images/generations`를 호출한다. 공식 호스트만 허용하며 키 누락 시 호출 전에 실패한다. 기존 구독 어댑터로 자동 폴백하지 않는다. 기본 모델은 판정·비전 `gpt-6.1-sol`, 이미지 `gpt-image-2.6-sunburst`로 정한다(모델 선택은 구현 기본값). 키는 기존 로컬 .env에서 필요한 항목만 실행 루트에 연결하며 어떤 출력·Git에도 넣지 않는다.

## 작업·검증

- [x] 공식 URL·참조 편집·생성·키 누락·잘못된 이미지 응답·비밀값 마스킹의 오프라인 검사를 먼저 작성한다.
- [x] 공용 이미지 클라이언트와 ImageModel 포트 연결, 예시 설정과 안내를 고친다.
- [x] 기존 이미지·비전·공식 요청 형식 및 기준 사진 공정의 회귀 검사를 실행한다.
- [x] 기존 서버와 같은 데이터·보존용 wrapper를 쓰는 새 실행본에 변경 파일만 반영한다. 정지된 페르소나 변경은 되살리지 않는다.
- [x] 공식 API의 모델 접근 확인(무료 조회) 뒤 텍스트 1회·비전 1회·합성 참조 이미지 편집 1회로 연결을 검증한다. 실제 인물 결과는 새로 생성하거나 승인하지 않는다.
- [x] 서버를 새 실행본으로 재시작하고 실제 설정·API 응답·기존 파일 해시를 확인한다. Git commit/push는 하지 않는다.

## 주의할 검증 경계

모델 목록 접근만으로 생성 성공을 주장하지 않는다. 미확인 이미지 비용은 0으로 기록하지 않는다. 합성 사진 편집 성공은 실인물 동일성·영상 동작 품질 보장이 아니다. 키와 원본 자료를 테스트 fixture로 넣지 않는다.
